# 万达影院城市映射方案详细设计

## 1. 问题背景

万达影院列表接口按城市查询时一次只返回该城市的影院，传无效 ID（如 `-1`）时返回全部 854 家影院但**不含城市信息**。前端规则新建弹框需要：

- **城市-影院联动**：选中城市后只展示该城市下的影院
- **`includeCinemaCodes` 准确**：保存时需 `cityId_storeId` 格式，要求每条影院数据有准确的 `city_id`

现有方案（地址解析）准确率不足，循环 252 个城市性能太差。

## 2. 整体方案

在**后端**维护一张 `storeId ↔ cityId` 映射表，由定时任务每晚刷新。前端调新接口一次获取全量影院+城市信息。

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  前端规则弹框    │ ──→ │  GET /list-with-city│ ──→ │  万达 API        │
│                 │     │  (返回影院+城市)   │     │  (locationId=-1)│
│  getAllCinemaList│ ←── │                   │ ←── │                 │
└─────────────────┘     └──────┬───────────┘     └─────────────────┘
                               │ 查表
                               ↓
                        ┌──────────────┐
                        │ wanda_cinema │
                        │ _city 映射表  │
                        └──────┬───────┘
                               ↑ 每晚12点写入
                        ┌──────────────┐
                        │  定时任务     │
                        │ (遍历252城市) │
                        └──────────────┘
```

## 3. 数据库设计

### 3.1 新建表 `wanda_cinema_city`

```sql
CREATE TABLE wanda_cinema_city (
  id            INT AUTO_INCREMENT PRIMARY KEY COMMENT '自增主键',
  store_id      INT NOT NULL COMMENT '万达影院storeId',
  cinema_name   VARCHAR(200) NOT NULL COMMENT '影院名称',
  city_id       INT NOT NULL COMMENT '万达城市ID（对应homepage/city.api的id）',
  city_name     VARCHAR(100) NOT NULL COMMENT '城市名称',
  update_time   DATETIME NOT NULL COMMENT '更新时间',
  UNIQUE KEY uk_store_id (store_id),
  KEY idx_city_id (city_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='万达影院-城市映射表';
```

### 3.2 字段说明

| 字段          | 来源                                       | 说明               |
| ------------- | ------------------------------------------ | ------------------ |
| `store_id`    | 影院列表接口 `cinemaInfoList[].storeId`    | 万达影院唯一标识   |
| `cinema_name` | 影院列表接口 `cinemaInfoList[].cinemaName` | 影院名称，便于排查 |
| `city_id`     | 按城市查影院时使用的 `locationId`          | 万达城市ID         |
| `city_name`   | 城市列表接口 `city[].name`                 | 城市名称，便于排查 |
| `update_time` | 定时任务执行时间                           | 用于判断数据时效   |

## 4. 后端接口设计

### 4.1 新增接口：获取全量影院（含城市信息）

```
GET /wanda-film-ser/cinema/cinema/list-with-city
```

**请求头**（与现有 `proxyWandaFilmApi.js` 一致）：

| 请求头            | 必填 | 说明         |
| ----------------- | ---- | ------------ |
| `user-token`      | 是   | 万达用户令牌 |
| `user-identifier` | 是   | 万达用户标识 |

**处理逻辑**：

```
1. 调万达 API: GET /cinema/by_locationid_v6_4.api?locationId=-1
   → 返回全部 854 家影院（含 storeId、cinemaName、address 等）
2. 查询 wanda_cinema_city 表，获取所有 store_id → city_id 映射
3. 遍历影院列表，为每条数据补上 city_id、city_name
4. 返回增强后的影院列表
```

**响应格式**：

```json
{
  "code": 0,
  "data": {
    "cinemaInfoList": [
      {
        "storeId": 6698,
        "cinemaName": "上海寰映影城太阳宫店",
        "address": "上海市虹口区...",
        "city_id": 430,
        "city_name": "上海",
        ...其他原始字段...
      }
    ]
  }
}
```

**异常处理**：

| 场景                        | 处理                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------- |
| 映射表中无该 `storeId` 记录 | **不允许出现**。`list-with-city` 接口启动时检查映射表是否为空，若为空则自动触发一次刷新 |
| 刷新过程中某个城市失败      | 全量收集失败，整体中止，不写入任何数据，旧数据继续使用                                  |
| 万达 API 完全不可用         | 返回 502，前端提示"服务暂不可用"                                                        |

> **`city_id` 不允许为 null**：`list-with-city` 接口保证返回的每条影院数据都带有有效的 `city_id` 和 `city_name`。若映射表为空，接口内部自动触发刷新，刷新完成后再返回数据。

### 4.2 新增接口：手动触发刷新映射（调试用）

```
POST /wanda-film-ser/cinema/cinema/refresh-city-map
```

用于手动触发映射重建，方便首次部署或紧急修复。返回刷新的影院数量。

## 5. 定时任务设计

### 5.1 执行时机

每晚 00:00（北京时间），通过 `node-cron` 调度。

### 5.2 执行逻辑

定时任务遍历城市时，需要调用万达 API，调用时需要 `user-token` 和 `user-identifier` 身份标识。这些信息从**影院登录信息表**中读取。

#### 身份标识获取

从 `app_name = 'wanda'` 的登录记录中读取，数据库表为 `login_record`：

| 定时任务需要的字段 | 对应万达 API 的请求头 | 来源表字段                |
| ------------------ | --------------------- | ------------------------- |
| `user-token`       | `X-RY-TOKEN`          | `login_record.session_id` |
| `user-identifier`  | `X-RY-USER`           | `login_record.tid`        |

**SQL 查询示例**：

```sql
SELECT session_id, tid, mobile
FROM login_record
WHERE app_name = 'wanda'
  AND session_id IS NOT NULL
  AND session_id != ''
  AND tid IS NOT NULL
  AND tid != ''
ORDER BY update_time DESC
LIMIT 1;
```

取最新一条有有效 `session_id` 和 `tid` 的记录。首次部署时需先在系统中维护好万达的登录信息（通过「影院登录信息维护」页面添加 `app_name = 'wanda'` 的记录，填入 `session_id` 和 `tid`），定时任务才能正常执行。

**代码示例**（定时任务中获取）：

```javascript
const mysql = require("mysql");
const pool = mysql.createPool({
  /* 数据库连接配置 */
});

async function getWandaCredentials() {
  const sql = `SELECT session_id, tid FROM login_record
               WHERE app_name = 'wanda'
                 AND session_id IS NOT NULL AND session_id != ''
                 AND tid IS NOT NULL AND tid != ''
               ORDER BY update_time DESC LIMIT 1`;
  return new Promise((resolve, reject) => {
    pool.query(sql, (err, rows) => {
      if (err) return reject(err);
      resolve(rows[0] || null);
    });
  });
}

// 使用示例
const creds = await getWandaCredentials();
if (!creds) {
  throw new Error("未找到万达登录信息，请先维护 login_record");
}
const headers = {
  "user-token": creds.session_id,
  "user-identifier": creds.tid
};
```

#### 执行逻辑

采用 **批量收集 + 统一时间戳 + 写入后清理** 策略，保证并发安全：

```
1. batchTime = new Date()          ← 记录本批次唯一时间戳
2. 全量收集（任一城市失败则整体中止）:
   for each city in 城市列表(252个):
     调万达 API 获取该城市影院列表
     cinemas → 收集到 allMappings[]
3. batchUpsert(allMappings, batchTime):
   INSERT ... ON DUPLICATE KEY UPDATE
   → 所有记录 update_time = batchTime（同一时刻）
   → 写入期间旧数据仍在表中，list-with-city 正常读取
4. cleanExcept(batchTime):
   DELETE FROM wanda_cinema_city WHERE update_time != batchTime
   → 只删除非本批次的数据（已下线的影院）
```

#### 并发安全说明

| 时刻                    | 表中的数据             | list-with-city 读到什么   |
| ----------------------- | ---------------------- | ------------------------- |
| 收集阶段                | 旧数据（前一晚的批次） | ✅ 正常返回旧数据         |
| 写入阶段（batchUpsert） | 旧数据 + 新数据并存    | ✅ 旧数据完整，可正常读取 |
| 清理阶段（cleanExcept） | 只保留本批次新数据     | ✅ 全部到位后才切换       |
| 任一城市失败            | 不写入不清理           | ✅ 旧数据完整保留         |

#### 定时任务注册

在 `cron/index.js` 中注册，每晚 00:05 执行：

```javascript
cron.schedule("5 0 * * *", async () => {
  // 获取登录凭证 → 获取城市列表 → 全量收集 → batchUpsert → cleanExcept
});
```

### 5.3 代码位置

**文件**：`auto-ticket-service/cron/wandaCinemaCityMap.js`

```javascript
const cron = require("node-cron");
const axios = require("axios");
const mysql = require("mysql");
const wandaSign = require("../middlewares/wandaSign");

// 每晚 00:00 执行
cron.schedule("0 0 * * *", async () => {
  console.log("[WandaCityMap] 开始刷新影院城市映射...");
  await wandaSign.initWasm();

  // 1. 获取城市列表
  const cities = await getCityList();

  // 2. 遍历每个城市，获取该城市下的影院
  const now = new Date();
  for (const city of cities) {
    const cinemas = await getCinemaListByCity(city.id);
    for (const cinema of cinemas) {
      await upsertMapping(
        cinema.storeId,
        cinema.cinemaName,
        city.id,
        city.name,
        now
      );
    }
  }

  // 3. 清理已下线影院
  await cleanOldMappings(now);

  console.log("[WandaCityMap] 刷新完成");
});
```

### 5.4 首次数据填充

首次部署时，可通过 `POST /refresh-city-map` 手动触发，或等待次日凌晨自动执行。在首次执行完成前，前端页面城市联动功能不可用（影院列表无城市信息），但不影响其他功能。

## 8. 数据一致性保障

| 场景             | 处理方式                         |
| ---------------- | -------------------------------- |
| 万达新增影院     | 定时任务下次执行时自动发现并录入 |
| 万达影院下线     | 定时任务清理环节自动删除         |
| 万达城市变更     | 定时任务重新遍历时自动更新       |
| 定时任务执行失败 | 下次执行时自动覆盖旧数据         |
| 首次部署数据为空 | 前端降级，不阻塞功能             |

## 9. 安全与权限

- `list-with-city` 接口无需额外鉴权（复用现有 `user-token` / `user-identifier`）
- `refresh-city-map` 接口需管理员权限或 IP 白名单
- 数据库连接复用现有连接池
