# electron-pure-admin 项目详细说明文档

> 版本：6.3.38 | 生成日期：2026-06-04

## 1. 项目概述

**electron-pure-admin** 是一个基于 **Electron + Vue 3** 的影院票务管理系统，核心业务是**多平台电影票自动化报价、出票、锁座、订单管理**。系统对接猎人、省APP、芒果、蚂蚁、洋葱、影划算、商展、哈哈、守兔、麻花等多个票务平台，实现跨平台的自动化运维。

脚手架基于 [vue-pure-admin](https://github.com/xiaoxian521/pure-admin-thin)。

### 技术栈

| 类别 | 技术 |
|------|------|
| 桌面框架 | Electron 30 |
| 前端框架 | Vue 3.4 + Vite 5 |
| UI 组件库 | Element Plus 2.7 |
| 状态管理 | Pinia 2 |
| 样式 | TailwindCSS 3 + SCSS |
| HTTP | Axios + axios-retry |
| 图表 | ECharts 5 |
| 电子表格 | ExcelJS |
| 加密 | CryptoJS |
| 测试 | Jest 30 |
| 打包 | electron-builder 24 |
| 语言 | JavaScript（主）+ TypeScript（类型检查）|

## 3. 核心架构设计

### 3.1 平台适配器体系（Adapter Pattern）

系统采用**适配器模式**实现多平台对接，核心抽象层位于 `src/common/core/`。

#### 类继承关系

```
BasePlatformAdapter (平台适配器基类)
  ├── PlatformAdapter (通用适配器 - 参数转换 + HTTP 调用)
  │     ├── ShengPlatformAdapter (省APP - 额外 seatInfo 处理)
  │     └── LierenPlatformAdapter (猎人 - 额外 ruleId/会员价逻辑)
  └── 各平台可扩展自定义适配器

BaseOfferQueue (报价队列基类)
  └── 各平台报价队列 (LierenOfferQueue, HahaOfferQueue, ...)

BaseTicketQueue (出票队列基类)
  └── 各平台出票队列

BaseOrderFetcher (订单获取基类)
  └── 各平台订单获取器 (LierenOrderFetcher, ...)

BaseOfferPrice (报价逻辑基类)
  └── 各影院报价逻辑 (SFC, UME, LUMI, ...)

BaseBuyTicket (出票逻辑基类)
  └── 各影院出票逻辑
```

### 3.2 平台配置中心

[src/common/platform/configs/platform-config.js](src/common/platform/configs/platform-config.js) 是所有平台配置的统一管理中心，每个平台定义：

| 配置项 | 说明 |
|--------|------|
| `features` | 平台特性：价格步进、是否需要规则ID、是否需要解锁、是否需要确认接单等 |

### 3.3 报价队列调度机制

[src/common/core/BaseOfferQueue.js](src/common/core/BaseOfferQueue.js) 实现了基于**按系列有限并发**的报价调度：

- **队列排序**：按 `offer_end_time`（报价截止时间）升序，紧急订单优先处理
- **并发控制**：不同系列（如不同影院）可并行报价，同系列限并发（默认每系列最多 2 单同时报价）
- **过期过滤**：距报价截止时间小于阈值（`minOfferHandleEndTime`）的订单自动跳过
- **超时保护**：单个订单报价超过 `offerHandleTimeout`（默认 15 秒）自动超时释放
- **防重复**：通过 `handledOrders` Map 避免同一订单重复入队（容量上限 100）

### 3.4 报价流程

```
1. 平台订单获取器 (OrderFetcher) 定时拉取待报价订单
       ↓
2. 报价队列 (OfferQueue) 接收新订单，按截止时间插入队列
       ↓
3. 调度器 (startProcessingQueue) 按系列并发限制选取可执行订单
       ↓
4. singleOffer() 执行报价链路：
   ├── getOfferPriceFun() 获取报价策略实例（工厂模式）
   ├── getEndOfferPrice() 计算最终报价
   ├── dynamicPrice() 动态调价
   ├── getRuleId() 获取规则ID（猎人平台需要）
   └── submitOffer() 提交报价到平台
       ↓
5. addOrderHandleRecord() 记录报价结果到数据库
```

### 3.5 出票流程

```
1. 订单获取器拉取已接单待出票订单
       ↓
2. 出票队列 (TicketQueue) 管理出票任务
       ↓
3. 解锁座位 (unlockSeat) — 根据平台配置决定是否需要
       ↓
4. 提交取票码 (submitTicket) — 各平台参数格式不同，通过适配器转换
       ↓
5. 转单处理 (transferOrder) — 出票失败时自动转单
```

## 9. 关键设计模式

| 模式 | 应用位置 | 说明 |
|------|----------|------|
| **适配器模式** | `PlatformAdapter` | 统一不同平台的接口差异，提供一致的报价/出票/解锁接口 |
| **工厂模式** | `OfferPriceFactory` | 根据影院类型创建对应的报价策略实例 |
| **模板方法模式** | `BaseOfferQueue` / `BaseTicketQueue` | 基类定义算法骨架，子类实现具体步骤（如 `fetchOrders`、`getRuleId`）|
| **策略模式** | 各平台报价逻辑 | 不同影院使用不同的报价计算策略 |
| **配置驱动** | `platform-config.js` | 新增平台只需添加配置，无需修改核心代码 |
| **队列模式** | `OfferQueue` / `TicketQueue` | 异步任务调度，支持并发控制和优先级排序 |

## 10. 扩展指南

### 添加新平台

1. 在 [platform-config.js](src/common/platform/configs/platform-config.js) 添加平台配置
2. 在 `src/common/platform/adapters/` 创建适配器（继承 `BasePlatformAdapter`）
3. 在 `src/common/platform/queues/` 创建报价队列（继承 `BaseOfferQueue`）
4. 在 `src/common/platform/fetchers/` 创建订单获取器（继承 `BaseOrderFetcher`）
5. 在 `src/common/platform/apis/` 创建 API 模块
6. 在 `src/utils/http/` 创建请求实例
7. 在 `src/store/platTokens.js` 添加平台 Token 管理

详细步骤参见 [src/common/MIGRATION_GUIDE.md](src/common/MIGRATION_GUIDE.md)。

### 添加新影院

1. 在 `src/common/core/common.js` 的影院映射中添加新影院标识
2. 在 `src/common/autoTicket/` 中创建对应的报价/出票策略
3. 在 `src/store/cinemaList.js` 中添加影院配置

## 11. 注意事项

- 各平台 HTTP 实例独立管理 Token，存储在 `localStorage`
- 报价截止时间判断可通过 `skipOfferEndTimeCheck` 配置跳过（如蚂蚁平台）
- 芒果平台报价价格需要乘以 100（分为单位）
- 省APP需要额外处理 `seatInfo` 和 `supplierCode`
- 猎人平台报价需要额外获取 `ruleId` 和 `memberPrice`
- 麻花平台不需要解锁座位（`unlockBeforeTicket: false`）
- 系统支持测试订单模式（`isTestOrder`），测试单不实际提交报价
