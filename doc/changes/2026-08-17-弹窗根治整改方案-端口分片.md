## 二、方案 A：端口分片（核心）

### 原理
Chromium 的 6 连接限制是 **per (host, port)**。让同一服务器在 3000/3001/3002 三个端口同时监听 → 客户端连接容量 **6 → 18 槽**。
排队时间 ∝ 请求密度 ÷ 槽数——槽数 ×3 后，cached-ids 等内部接口（服务器处理 <100ms）排队时间趋近于 0，**永不超时**。

**选型说明**：原设计为域名分片（api2/api3 子域名指向同一 IP），实施时改为端口分片——两者同样按 (host, port) 计槽，端口分片**免 DNS 配置、不依赖域名**，仅需安全组放行端口。

### 改动清单

**1. 新增 `src/common/serverHost.js`**（42 行）
```javascript
// 分片端口列表（3001/3002 需服务器安全组/防火墙开放，后端 app.js 已多监听）
const HOSTS = [
  "http://47.113.191.173:3000",   // 主端口（保持原直连地址，零依赖）
  "http://47.113.191.173:3001",   // 分片 2
  "http://47.113.191.173:3002"    // 分片 3
];
// 字符串 hash（djb2）→ 同一 URL 永远同一端口（连接复用，不会同接口跨端口）
export const getServerBaseUrl = url => {
  return HOSTS[djb2(url || "") % HOSTS.length];
};
export const getServerHosts = () => [...HOSTS]; // 调试/单测用
```

### 影响分析

| 维度 | 影响 | 缓解 |
|---|---|---|
| 排队容量 | 6 → 18 槽（×3） | - |
| 服务器连接数 | 客户端 keep-alive 连接最多 18 条（原 6）——Node 单机轻松承载（HTTP 层连接，非 MySQL 连接） | 无 |
| 端口依赖 | 3001/3002 未开放/被占用 → 该端口请求直接失败（ECONNREFUSED）——**新增风险点** | ① 上线前 curl 验证 3 端口 ② 分片函数 hash 稳定，可随时改回单端口（1 行）③ 主端口保持原直连，即使分片端口异常也只影响 2/3 请求 |
| CORS | 若生产渲染层与 API 同源加载，分片到 3001/3002 的请求变为跨域，需服务器放行 | **上线前必须用真实客户端（浏览器/Electron）验证无 CORS 报错**——curl 不执行 CORS，验证不了；域名分片方案同样有此要求 |
| 同接口跨端口 | 不会（hash 按完整 URL，稳定） | - |
| 服务器访问日志 | 出现 3 个监听端口的请求 | 无影响（已验证服务器无 host 校验） |
| 本地 dev | IS_DEV 分支不涉及分片 | - |
| 单测/构建 | 新增 1 个纯函数 + 5 条单测（serverHost.test.js） | - |

## 三、附带优化

### 1. cached-ids 5s 超时 + 弹窗静默化（sv-api.js + sv-request.js）
- **修订（用户确认）**：cached-ids 是**可降级接口**——超时/失败 → 回源完整查询链（thirdPartyIdsCache 回源机制已有）。**应快速失败快速回源**，而不是延长超时干等：
  - 5s 超时（原设计，7s/10s 方向错误已撤销）：排队 5s 未轮到 → 快速失败 → 立即回源实时查询（1-2s）→ 总耗时比等 10s 更短
  - 分片后排队大幅减少 → cached-ids 超时频率本身下降；偶发超时走"快速失败 + 回源 + 静默化"
- 静默化：sv-request 拦截器对 cached-ids 网络错误**不弹窗**（D3 日志/攒批上传保留）——可降级接口失败不应打扰用户

### 2. grab 弹窗静默化（lieren-request.js 错误拦截器，1 处条件）
- 改动：网络错误分支中，URL 含 `/openapi/order/grab` → **不弹 ElMessage**（D3 本地日志 + 攒批上传保留）。
- 依据：grab 有 6s tick 循环自动兜底，弹窗无业务价值纯噪音（8-16 用户 11 的 198 条 grab 弹窗）。
- 影响：用户不再被 grab 失败打扰；排查仍可查 D3 日志/opera_record。

### 3. grab 超时 5s → 6s（lieren-api.js，1 行）
- 改动：`queryStayOfferList` 请求超时由 5s 调为 6s。
- 依据：预算链对齐——服务器 openApiFactory 对 grab 类接口转发 4s + 回传 1s = 5s 恰好卡客户端 5s 临界，代理故障期表现成"超时"而非"快速失败"；6s 让服务器 4s 失败能及时返回，tick 循环正常兜底（见 `auto-ticket-service/middlewares/openApiFactory.js:139`）。
- 影响：失败路径更符合"快速失败"预期；弹窗已静默化，无噪音增加。
