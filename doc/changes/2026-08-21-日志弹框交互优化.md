# 日志弹框交互优化说明

> 日期：2026-08-21
> 状态：已实施（待提交，版本 6.6.44）
> 用途：明细/异常日志 Tab 交互调整 + 出票记录日志查看权限收口 + 后端 type 多值支持

---

## 一、需求（用户裁定）

1. 出票记录明细日志查询：增加"是否查看报价阶段日志"开关，默认不查看，勾选后查看（类似"仅时间线"开关）；
2. 报价记录、出票记录：明细日志 Tab 放到异常日志前面；
3. 出票记录仅失败订单支持查看日志，开发环境除外。

## 二、修改内容

### 前端 `src/components/HistoryTicketRecord.vue`

| 改动 | 说明 |
| --- | --- |
| "查询日志"按钮 `v-if="IS_DEV \|\| order_status === '2'"` | 生产仅失败订单可查（6.6.41 曾放开成功订单，本次按业务收回）；`IS_DEV = import.meta.env.DEV` |
| Tab 顺序对调 + 默认激活 trace | 明细日志在前，打开弹框默认展示明细 |
| queryLog 打开弹框自动 queryTrace | 替代原"切 Tab 才自动查"（默认 tab 即明细，打开即可见） |
| 新增 `traceShowOffer` 开关"查看报价阶段日志" | 默认 false → queryTrace 传 `type: "2,3"`（只看拉单+出票阶段）；勾选后不传 type（全量含报价） |

### 前端 `src/components/HistoryOfferRecord.vue`

| 改动 | 说明 |
| --- | --- |
| Tab 顺序对调 + 默认激活 trace | 同出票记录 |
| queryLog 打开弹框自动 queryTrace | 同出票记录 |

（报价记录明细本就传 `type: 1` 只看报价阶段，不受开关影响）

### 后端 `auto-ticket-service/api/traceFile.js`

`findTrace` 的 type 过滤支持**逗号分隔多值**（`"2,3"` 等）：`String(type).split(",").map(trim).filter(Boolean)` 后 `includes(upload_type)` 匹配；空值仍为全量。兼容原有单值传参（如 `type=1`）。

## 三、验证

- 后端：`node --check` 通过；type 多值逻辑单测（2,3 排除 1 / 包含 2,3 / 空=全量）全部符合预期
- 前端：eslint 两个组件无错误；watch 与显式 queryTrace 无重复查询（traceAutoQueried 置位逻辑核对）
- jest：相关套件通过

## 四、回归风险

- **低**：改动均为展示层交互 + 后端 type 过滤增强；`type` 多值解析对旧单值传参完全兼容
- 行为变化提醒：① 生产环境成功订单不再显示"查询日志"按钮（6.6.41 放开的功能收回）；② 明细日志默认不含报价阶段（勾选后恢复全量）；③ 打开弹框自动查明细（原需手动切 Tab）
