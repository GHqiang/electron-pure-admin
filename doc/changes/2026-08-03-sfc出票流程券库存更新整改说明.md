# SFC 出票流程券库存更新整改说明

> 日期：2026-08-03
> 状态：**已实施**
> 关联文档：[2026-07-30-券库存批量更新改造说明.md](./2026-07-30-券库存批量更新改造说明.md)（7 平台批量改造，本次为 SFC 系列专项）
> 背景：SFC 系列出票流程券库存更新未纳入 7 平台批量改造，且存在 1 个既有 bug（`this.curPhone` 从未赋值导致异步绑券后的库存修正失效），经对照其它系列排查后修复。

---

## 1. 背景与排查

### 1.1 SFC 券库存更新链路（改造前）

SFC 与其他 7 平台不同，出票流程的券库存更新走**公共 helper**（`buyTicket/common/cardQuanHelper.js`），而非各平台自有 `cardQuanManage.js`：

```
sfc/cardQuanManage.js
  ├─ 报价前 getQuanTypeListByApp()  → getQuanTypeListByAppCommon()   （只读查询，不刷新库存）
  └─ 出票流程 useQuanOrCard()
       ├─ 用券前：updateQuanStock({ quan_stock: quanStock, ... })      （L410）
       └─ useQuan → 异步绑券 getNewQuan(asyncFlag=1)
            └─ 绑券后：updateQuanStock({ quan_stock: quanStock - ticket_num + bandQuanList.length, phone: this.curPhone })  （L884）
       └─ 均委托 updateQuanStockCommon() → 循环内逐条 svApi.updateQuanType()
sfc/buyTicket.js
  └─ 出票成功后：await updateQuanStock({ quan_stock: quanStock - ticket_num, phone: this.currentPhone })  （L703）
```

### 1.2 对照其它系列确认的差异

| 环节 | 7 平台（wanda/lma 等） | SFC（改造前） | 结论 |
| --- | --- | --- | --- |
| 出票后库存扣减 | 出票成功 `quan_stock: quanStock - ticket_num` | 有（buyTicket.js:703，`await`） | ✅ 一致 |
| 用券前库存写入 | 无 | 有（L410 写拉取数 quanStock） | SFC 特有设计（"无论是否入库券都更新库存"），保留 |
| 服务端取券/绑券后修正 | lma 无修正（下次拉取覆盖） | 有修正公式（`- ticket_num + bandQuanList.length`）但**从未生效** | ❌ 问题 A |
| 落库方式 | 批量（batchUpdateQuanType 事务） | 逐条 `svApi.updateQuanType`（N 次 HTTP，无事务） | ❌ 未纳入批量改造 |
| 空手机号防御 | 有（`if (!phone)` 跳过） | 无 | ❌ 未覆盖 |

## 2. 发现的问题

### 2.1 问题 A：`this.curPhone` 从未赋值（唯一问题）

`sfc/cardQuanManage.js` 中 `this.curPhone` 仅在构造时初始化为 `""`（L51），**从未被赋值**。异步绑券后的库存修正（L884）使用 `phone: this.curPhone` 恒为 `""`：

- 修复前（逐条 `findIndex(i => i.phone === phone)`）：空 phone 匹配不到任何真实手机号条目 → **修正静默失效**
- 修复后（`updateQuanStockCommon` 空 phone 防御）：显式跳过并记日志（`跳过空手机号券库存更新`）→ 问题暴露

**影响**：服务端绑券后的库存修正（`quanStock - ticket_num + bandQuanList.length`）从未写入 DB，绑定的新券未反映到库存。

### 2.2 排查过程中的误报（已纠正）

曾误判"出票成功后无库存扣减"（问题 B），原因是**检查不全面**（只查了 `cardQuanManage.js`，遗漏 `buyTicket.js`）。经核对：`sfc/buyTicket.js:703` 出票成功后**已有** `await updateQuanStock({ quan_stock: quanStock - ticket_num, ... })` 扣减，与 7 平台一致。误加的重复扣减代码已删除，未上线。

## 3. 整改内容

### 3.1 `updateQuanStockCommon` 切批量（`buyTicket/common/cardQuanHelper.js`）

收集 `updateList` 后调用 `batchUpdateQuanStockWithSync`（批量落库事务原子性 + 统一触发一次猎人规则同步），替代循环内逐条 `svApi.updateQuanType`：

```js
if (updateList.length) {
  await batchUpdateQuanStockWithSync({ list: updateList, app_name, logger });
} else {
  logger?.infoSave?.("SFC 无匹配券类型，跳过库存更新", { app_name, quan_flag, phone });
}
```

- 入参 `update` 增加 `quan_value`（批量规则同步匹配用，落库时被 `dbList` 剥离）
- 空 phone 防御：`if (!phone)` 跳过并记日志（与 7 平台一致）
- 注：SFC 原实现不触发猎人规则同步，纳入后与 7 平台一致（无关联规则时走"无关联规则"分支，无副作用）

### 3.2 修复问题 A（`sfc/cardQuanManage.js`）

`useQuanOrCard` 入口记录当前出票手机号：

```js
// 记录当前出票手机号：异步绑券（getNewQuan asyncFlag=1）内更新库存时依赖此值
this.curPhone = curPhone;
```

`curPhone` 来自 `buyTicket.js` 传入的 `this.currentPhone`（真实登录手机号）。修复后异步绑券修正恢复生效。

**修复后完整链路（无重复扣减）**：

| 顺序 | 位置 | 写入值 | 说明 |
| --- | --- | --- | --- |
| 1. 用券前 | cardQuanManage.js L410（裸调用） | `quanStock`（拉取数） | 发起于出票前，出票流程耗时秒级，必然先完成 |
| 2. 出票后 | buyTicket.js L703（await） | `quanStock - ticket_num` | 原有逻辑，与 7 平台一致 |
| 3. 异步绑券后 | cardQuanManage.js L884（修复 A 后） | `quanStock - ticket_num + bandQuanList.length` | 绑券网络耗时秒级，最后写入精确值 |

三步均用同一 `quanStock` 变量（useQuanOrCard → useQuan → getNewQuan 透传），无取值偏差、无重复扣减。

### 3.3 修复 `updateQuanStock` 引用已删除函数导致的崩溃（`sfc/cardQuanManage.js`）

**问题**：`updateQuanStock` 曾被重写为"循环内调用 `singleUpdateQuanStock(updateParams)`"并 `import { singleUpdateQuanStock }`——该函数已在 7 平台批量改造中**删除且不再导出**，import 值为 `undefined`，调用即抛 `TypeError`：

- 用券前调用点（cardQuanManage.js L410，裸调用）：异常被吞，库存更新不生效
- 出票后调用点（buyTicket.js L703，`await`）：异常抛出 → 被出票流程 catch → `lastHandle` 跳过 → **每个 SFC 用券订单出票中断**

**修复**：对齐 7 平台出票后路径，改为收集 `updateList` 后一次 `batchUpdateQuanStockWithSync`（批量落库 + 统一规则同步），并补空 phone 防御：

```js
async updateQuanStock(params) {
  const { quan_stock, quan_flag, phone, app_name, quan_value } = params;
  // 空 phone 防御（对齐 wanda 等平台）
  if (!phone) { this.logger.infoSave("跳过空手机号券库存更新", {...}); return; }
  let targetQuanList = await this.getTargetQuanByApp(app_name, quan_flag);
  const updateList = [];
  targetQuanList?.forEach(item => { ...构建 updateParams（含 end_use_time 判断）; updateList.push(updateParams); });
  // 批量落库 + 统一触发一次规则同步（保持出票后路径异步不阻塞）
  batchUpdateQuanStockWithSync({ list: updateList, app_name, logger: this.logger });
}
```

> 注：重写后 `updateQuanStockCommon`（`cardQuanHelper.js`）已无调用方，保留定义备用。

### 3.4 `sfc/buyTicket.js` 出票后扣减调整（工作区既有改动，核对确认合理）

相对 HEAD 的既有改动（非本次新增），与重写后的 `updateQuanStock` 入参契约对齐，核对确认合理：

| 项 | HEAD 原状 | 调整后 |
| --- | --- | --- |
| 触发条件 | `offer_type === "1" && is_store != 1`（仅非入库券） | `offer_type === "1" && quan_code`（入库券/非入库券用券后均扣减） |
| 入参 | `ticket_num`（递减模式） | `quan_stock: quanStock - ticket_num`（直写模式） |

配套：`useQuanOrCard` 返回值透传 `quanStock`（`useRes` 解构新增），供出票后直写使用。

### 3.5 冗余日志清理（`sfc/cardQuanManage.js`）

删除 5 处全量打印日志（每页/每次拉券重复、体积大），保留精简版 `获取优惠券列表返回`（5 字段）与数量提示：

- `连续获取目标券返回`（每页全量券号列表）
- `按照券类型或者券标识匹配目标券列表` × 2（全量券对象，每条 40+ 字段）
- `连续获取券最终返回`（全量 quanData）
- `连续获取目标券返回结果`（递归拉券全量返回）

## 7. 复盘

本次排查出现一次误报（问题 B），教训：

1. **检查范围必须完整**：出票流程跨多个文件（`buyTicket.js` 主流程 + `cardQuanManage.js` 卡券逻辑），只 grep 单文件会遗漏；wanda 的出票后扣减就在 `buyTicket.js:645`，sfc 同样在 `buyTicket.js:703`——对照其它系列时应先确认"对应位置"是否存在
2. **改动前先全量搜调用链**：`updateQuanStock` 的调用点应全局 grep（`src/common/autoTicket/buyTicket/sfc/` 全目录），而非单文件
3. 误加的重复扣减代码在文档同步前已被用户发现并删除，未上线、未产生实际影响
