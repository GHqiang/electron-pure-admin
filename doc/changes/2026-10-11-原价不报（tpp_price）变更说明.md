## 3. 核心变更说明

1. **数据模型**：`rule_record.noOfferTppRule VARCHAR(255) NULL`。**NULL = 未配置**，存量规则行为完全不变；一条规则可配多条条件。
2. **表达式语法**（分号分隔多条，命中任一即不报）：`>50` / `>=50` / `<30` / `<=30`；`30-80`（区间内，**闭区间**含端点）；`!30-80`（区间外）。解析器为新写的纯函数 `parseNoOfferTppRule` / `isTppPriceNoOffer` / `formatNoOfferTppRule` / `validateNoOfferTppRule`。
3. **不复用 `calculateMarkup`**：它是加价链路，且其区间操作符 `<>` 判定为 `>= 下界 || <= 上界`（对任意数**恒真**）、`!<>` 语义与命名相反——复用会把坑一起继承。本次保持"一列 + 分号多条件"的**形态一致**、实现独立。
4. **生效点唯一**：`offerRuleMatch`（`src/utils/utils.js`）**末尾**（会员日过滤之后）新增一层过滤，覆盖全部 8 个影线系列（sfc/ume/h5ume/lma/wanda/chenxing/fenghuang/jinyi）。放末尾的理由：只影响"本来能匹配到规则"的订单，**不改变既有"按城市/影院/影厅/座位数筛选为空"的统计口径**。
5. **未配置即放行**：过滤层第一个判断 `if (!item.noOfferTppRule) return true`，存量规则零影响。
6. **平台报价规则跳过**：已同步猎人平台 + 固定价 + 字典开关 + 时段内的规则由平台报价、本地不参与算价，过滤跳过（与 B钱包加价同口径），避免"本地记录规则为空、平台照报"的错位与统计噪音。判定抽成 `isPlatQuotedRule`，与 `BaseOfferPrice` 的报价守卫**共用一份逻辑**，且**含时段条件**（猎人 23:00–9:00 时段外平台不报、本地算价，此时过滤必须生效）。
7. **失败原因编号取 15**：本分支存在未落地的 stash（WIP「报价失败原因整改」），其测试已占用 `13=超时或过期未提交`、`14=黑名单或售罄不报价`；`err_type` 会落库并按枚举展示，占用会导致后续该 WIP 落地时冲突、历史数据错标。故取 15，并在枚举里留注释说明 13/14 的预留。前端 `HistoryOfferRecord.vue` 遍历枚举，**无需改动**。
8. **边界处理**：`tpp_price` 为空/非数值/≤0 → 放行 + `info` 日志（避免字段缺失导致大面积不报）；表达式中无法识别的片段 → 忽略该片段 + `errorSave`，其余条件照常判定（保存时前端已用 `validateNoOfferTppRule` 阻断脏表达式）。
9. **配置 UI**：规则弹框新增「原价不报」——条件行（下拉：超过/不低于/低于/不高于/区间内/区间外 + 数字输入，含增删）与表达式输入框双向互转；表达式字符串是唯一存储，条件行是其可视化视图；列表在「报价/加价金额」列下方回显黄色徽标 `原价不报:原价>50`；保存时空值统一转 `null`。
10. **缺列兜底泛化**：原 `saveRuleRecordWithBWalletFallback` 泛化为 `saveRuleRecordWithNewColumnFallback(request, params, columns)`，`columns` 为**列元数据** `[{ column, label, isUnknown }]`：

    ```js
    const NEW_RULE_COLUMNS = [
      { column: "bWalletMarkup", label: "B钱包加价", isUnknown: isUnknownBWalletMarkupError },
      { column: "noOfferTppRule", label: "原价不报", isUnknown: isUnknownNoOfferTppRuleError }
    ];
    ```

    命中缺列时剔除对应字段重试并提示「rule_record 缺少 X 列，本次保存未包含**业务字段名**」，保留原 B钱包加价「未包含 B钱包加价」的文案粒度，同时避免复制第三份兜底函数。
11. **出票链路不改**：出票按已选定的规则 id 取规则，不做二次过滤；规则变更不追溯已出票订单。
12. **UI 默认行为（2026-10-11 追加）**：表达式为空时打开弹框默认呈现一行条件行（等价于点过一次「新增」，`ensureTppRuleRow()` 在 `open()` 的两个分支与 `resetForm()` 中调用；新增场景同时清空行状态避免残留）；点「新增」或自动补的那一行，下拉默认选中**区间外**（仍可切换其它操作符）。区间类条件需上下限都填才会写入表达式。
