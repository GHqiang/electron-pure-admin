# 影划算/票圣/麻花订单号关联整改说明

## 问题背景

票圣、麻花、影划算等平台存在报价单号与出票单号不一致的问题：
- 报价记录中的订单号为**平台报价单号**（如 `putOrderId`）
- 出票记录中的订单号原本保存的是**平台待出票列表ID**（即出票单号）
- 这导致：
  1. 从出票记录复制订单号去报价记录中搜索，找不到对应报价
  2. 业务排查问题需要来回切换，效率低下

## 解决方案设计

在出票记录中同时保存两个单号，并通过字段约定保证关联可查：

| 字段 | 含义 | 使用场景 |
|------|------|----------|
| `order_number` | **报价单号** | 主展示字段，与报价记录的 `order_number` 对齐，支持互查 |
| `plat_order_sn` | **平台出票单号** | 平台操作（解锁/提交/重出票）时使用，保留原始平台单号 |

## 前端查询与展示调整

### 1. 搜索逻辑

已修改 ([HistoryTicketRecord.vue](file:///d:/Electron/electron-pure-admin-fix/src/components/HistoryTicketRecord.vue#L554-L562))：

```javascript
// 订单号查询特殊处理：影划算/票圣/麻花出票记录的 order_number 存的是报价单号，
// 用户按出票单号搜索时需转成 plat_order_sn 才能命中
if (
  ["yinghuasuan", "piaosheng", "mahua"].includes(queryParams.plat_name) &&
  queryParams.order_number
) {
  queryParams.plat_order_sn = queryParams.order_number;
  delete queryParams.order_number;
}
```

说明：用户在出票记录页搜索时，无论输入的是**报价单号**还是**出票单号**，都能命中记录。

### 2. 列表展示

已修改 ([HistoryTicketRecord.vue](file:///d:/Electron/electron-pure-admin-fix/src/components/HistoryTicketRecord.vue#L197-L201))：

```html
<!-- 出票记录优先展示平台出票单号 plat_order_sn，缺失时用报价单号 order_number 兜底 -->

```

说明：出票记录列表保持展示**平台出票单号**（`plat_order_sn`），与本地改动前用户看到的单号一致；仅当出票单号缺失时才用 `order_number`（报价单号）兜底。用户看到的单号仍是原始出票单号。

## 影响范围

| 模块 | 影响 | 说明 |
|------|------|------|
| 出票抓取 | 影划算（无变化）、票圣（修改）、麻花（修改） | 仅调整字段赋值顺序，不影响出票流程 |
| 出票记录查询 | 修改搜索转换逻辑 | 支持两种订单号搜索，兼容性更好 |
| 出票列表展示 | 修改显示顺序 | 优先展示报价单号，便于互查 |
| 重新出票 | 无影响 | 日志查询使用 `order_number`，与入库一致 |
| 日志查询 | 无影响 | 同上 |
| 报价记录查询 | 无影响 | 报价记录的 `order_number` 本身就是报价单号，无需改动 |

## 验证要点

1. 抓取票圣/麻花待出票，检查出票记录：
   - `order_number` 是否为 `putOrderId`（报价单号）
   - `plat_order_sn` 是否为原始待出票列表ID

2. 从出票记录复制订单号，粘贴到报价记录搜索：
   - 应能找到对应报价记录

3. 对已出票订单执行重新出票：
   - 应能正常查询到日志并重新入队

4. 在出票记录搜索框输入**原始出票单号**：
   - 应能命中对应记录（通过 `plat_order_sn` 转换查询）

## 总结

本次整改对齐了影划算、票圣、麻花三个平台的订单号存储规则：
- `order_number` 统一存**报价单号**，保证出票↔报价双向互查
- `plat_order_sn` 保存原始**平台出票单号**，用于平台操作
- 前端搜索同时支持两种单号输入，展示优先报价单号
- 重新出票、日志查询等现有流程不受影响，继续正常工作
