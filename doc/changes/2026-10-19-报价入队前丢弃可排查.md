## 二、核心变更说明

### 1. A：未报价记录（用户可见）

- `BaseOfferQueue.handleNewOrder` 截止不足分支不再静默 `return`：写 1 行 `offer_record_fail`（`order_status="2"`、`err_type=16`、`err_msg` 含剩余 ms/阈值），然后返回。
- `LierenOfferQueue.fetchOrders` 过滤分支按 `getCinemaFlagDetail` 原因处理（**v5 口径**）：
  - **16 截止不足**：A+B+C1 逐单记录；
  - **17 无可用登录**：仅当 `hasAnyRoleLogin(app_name)` 为 true（同角色有人维护了该影院登录）时写 A+B+C1；同角色所有用户都无登录 → **不写库、不写日志**；
  - **18 系列/影院被禁用**：**不写库、不写日志**；
  - **19 影院未识别（映射表无 code/名称没匹配上）**：**不写库、不写日志**。
- 13 个必填列逐字段兜底；`rule` 取 `tokens.userInfo.rule`，取不到则跳过并留痕；`user_id` 由后端 JWT 覆盖。
- 入库走串行队列（积压 200），`{ silent: true }` 避免失败弹窗风暴；失败计数进 C2 摘要。
- 每个平台队列实例每日写行上限默认 **2000**（字典 `offerDiscardDailyLimit` 可覆盖；同一客户端跑多个平台队列时各算各的，lieren 是主要来源），超出只计数不写行，B 证据仍写；计数在 C2 摘要 `discard_record_dropped`（订单排查页「上限丢弃」列 / `pull-summary` 的 `discard_dropped` 可见）。
- 同一单进程内只写一次（`${plat_name}_${order_number}`，容量 500）；测试订单跳过。

### 2. B：L2 丢弃明细

- **只对 16/17 写**：每次丢弃直传 `traceUpload()`（`type=1`），不经过 `Logger` 字典开关；带 `order_number`、`reason`、`reason_detail`、`err_type`、`err_msg`、水位线、本轮返回条数。
- 18/19/同角色全无登录的无关订单**不写 B**。
- 上传失败计数 `trace_fail`，进 C2 摘要（trace 本身「失败不重试不告警」）。

### 3. C1：拉单返回（B 场景正向证据）

- lieren 对**相关订单**（可报价 / 17 同角色有人有登录）写 1 条 `报价队列-拉单返回` L2 明细（按订单号去重，容量 1000），字段含 `round_ts`、`fetch_timestamp`、`returned_count`、`filter_reason`、`cinema_code`/`cinema_name`；**19/18/同角色全无登录的无关订单不写 C1**。
- 之后若查不到该单任何记录，可据此判断「客户端是否拿到过这单」，不再只能靠「全空」反推；无关订单查不到属预期。
- 逐单直传（一次请求一个分片），串行 + 上限 200；不改后端契约。

### 4. C2：5 分钟拉单摘要

- `BaseOfferQueue._startFetchLoop.finally` 累加 `rounds/ok_rounds/fail_rounds/returned/filtered/enqueued/last_fetch_timestamp/max_round_gap_ms/trace_fail/evidence_dropped/discard_record_fail`；每 5 分钟 `logUpload` 写 1 条 L1（`order_number=""`、`des="报价队列-拉单摘要"`），不新增定时器。
- **`returned` 只计「影院映射存在 + 同角色有登录」的可纳入订单**；`filtered`（17 且同角色有人有登录）/`enqueued` 同样只针对可纳入订单。
- 一期只对 lieren 开启（`_pullSummaryEnabled`）。
- 用于回答「该时段客户端是否在正常拉单、可纳入订单的拉取/过滤/入队各多少」。

### 5. UI

- 「订单排查」页按优先级给结论：目标用户已拉到+丢弃 / 正常入队 / 异常缺口 / 证据上传失败 / **同角色其他用户有记录、目标用户无记录（本机配置原因 / 疑似未拉到）**。
- 记录表**不按用户过滤**，显示同角色所有记录并标注「目标用户 / 其他用户」，直接对照「谁有记录、谁没有」。
- 新增「本机配置对照」：用对照记录的 `cinema_code`/名称 + 本机映射/登录/禁用状态调用 `getCinemaFlagDetail`，解释 19/18/17，**不写任何日志**；并提示“查用户 B 请到 B 的客户端打开”。
- **统计页相关改动已全部下线**（不再有「拉单与入队前丢弃」模块、`/discard`、`/pull`）。

### 6. D2a 报表口径

- `offer_record_fail` 的「真实失败」聚合统一加 `(err_type IS NULL OR err_type < 16)`：`aggregateOfferFail`、`aggregateTrend`、`aggregatePlatform`、`aggregateDaily`。
- 历史 `stat_daily_record` 在新增枚举前不存在丢弃行，无需回填。
- 丢弃原因不再混入失败率：D2a 已从真实失败聚合中排除 `err_type>=16`；18/19 及同角色全无登录按无关订单不产生新行。统计页相关接口已下线。
