# 金逸系列首次出票目标座位缺失修复

## 日期

2026-07-11

## 问题描述

金逸系列在第一次出票时，获取目标列座位列表（`targetRow`）中不含目标座位（如 7排18座、7排17座），导致出票失败。点击"重新出票"再次执行时，目标列座位列表又包含了目标座位，出票成功。

### 日志对比

**第一次（失败）**—— `targetRow` 中 9 个座位，缺少 col 17、18：

```json
{
  "targetRow": [
    { "col": "3" },
    { "col": "20" },
    { "col": "1" },
    { "col": "19" },
    { "col": "22" },
    { "col": "4" },
    { "col": "21" },
    { "col": "2" },
    { "col": "7" }
  ],
  "lockseat": "7排18座 7排17座"
}
```

**第二次（重试成功）**—— `targetRow` 中 11 个座位，包含 col 17、18：

```json
{
  "targetRow": [
    { "col": "3" },
    { "col": "20" },
    { "col": "1" },
    { "col": "19" },
    { "col": "22" },
    { "col": "4" },
    { "col": "21" },
    { "col": "2" },
    { "col": "18" },
    { "col": "7" },
    { "col": "17" }
  ],
  "lockseat": "7排18座 7排17座"
}
```

## 根因分析

### 根因一（主要嫌疑）：`getSeatLayout` 仅取 `room_seat[0]`

`src/common/autoTicket/buyTicket/jinyi/seatManage.js` 中 `getSeatLayout` 方法：

```javascript
let seatObj = res?.data?.room_seat?.[0]?.seats || {}; // ⚠️ 只取了 [0]
let seatData =
  Object.entries(seatObj)
    .map(item => item[1]?.detail)
    ?.flat() || [];
```

金逸 API `getMoviePlaySeat`（`/hall/saleable/`）返回的 `room_seat` 是数组，每个元素对应一个座位分区。代码只处理了 `[0]`，丢弃了 `room_seat[1..n]`。若影厅座位跨多个分区且 API 返回顺序不固定，目标座位可能在第一次被丢弃、第二次恰好排在 `[0]` 中。

对比同文件中 `areaInfoList` 取的是**完整** `room_seat` 数组（`res1?.data?.room_seat`），以及凤凰系列的正确处理方式（`res.sectionSeats?.map(item => item.seats)?.flat()`）。

### 根因二（次要）：服务端 API 响应不一致

金逸 `/hall/saleable/` 接口在短时间内两次调用返回不同数量的座位，存在服务端数据延迟加载或缓存不一致的问题。

### 根因三（次要）：`getSeatParams` 缺少 `session_id`

报价阶段传了 `session_id`，出票阶段未传，可能使用不同登录态导致返回数据差异。

## 修复方案

采用**方案 B**：`getTargetSeat` 获取目标座位失败时增加重试机制，应对 API 数据延迟加载。

### 修改文件

| 文件                                                  | 修改内容                                  |
| ----------------------------------------------------- | ----------------------------------------- |
| `src/common/autoTicket/buyTicket/jinyi/seatManage.js` | `getTargetSeat` 方法增加 3 次重试查询逻辑 |

### 修改详情

在 `getTargetSeat` 方法中，当 `targetSeats.length != ticket_num` 时，延时后重新调用 `getSeatLayout` + `filterTargetSeats`，最多重试 3 次。每次重试间隔递增（1s / 1.5s / 2s）。

### 后续待办

- [ ] 方案 A（遍历所有 `room_seat` 分区）—— 需确认金逸 API `room_seat` 数组的实际结构后再实施
- [ ] 方案 C（`getSeatParams` 补充 `session_id`）—— 需确认不影响现有登录切换逻辑

## 测试验证

- [ ] 金逸系列正常出票流程（一次成功场景）不受影响
- [ ] 首次目标座位缺失时，重试后能成功获取
- [ ] 3 次重试均失败后正确返回 `TARGET_SEAT_FAILED` 错误码
- [ ] 重试耗时在可接受范围内（总计约 4.5 秒）

## 回归风险评估

- **低风险**：仅在获取目标座位失败时触发重试，不影响正常出票路径
- 重试时机在锁座之前，不会产生额外锁座或扣费操作
