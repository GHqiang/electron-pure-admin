# 金逸系列首次出票目标座位缺失修复

## 日期

2026-07-11

## 问题描述

金逸系列在第一次出票时，获取目标列座位列表（`targetRow`）中不含目标座位（如 7排18座、7排17座），导致出票失败。点击"重新出票"再次执行时，目标列座位列表又包含了目标座位，出票成功。

### 日志对比

**第一次（失败）**—— `targetRow` 中 9 个座位，缺少 col 17、18：

```json
{
  "targetRow": [
    { "col": "3" },
    { "col": "20" },
    { "col": "1" },
    { "col": "19" },
    { "col": "22" },
    { "col": "4" },
    { "col": "21" },
    { "col": "2" },
    { "col": "7" }
  ],
  "lockseat": "7排18座 7排17座"
}
```

**第二次（重试成功）**—— `targetRow` 中 11 个座位，包含 col 17、18：

```json
{
  "targetRow": [
    { "col": "3" },
    { "col": "20" },
    { "col": "1" },
    { "col": "19" },
    { "col": "22" },
    { "col": "4" },
    { "col": "21" },
    { "col": "2" },
    { "col": "18" },
    { "col": "7" },
    { "col": "17" }
  ],
  "lockseat": "7排18座 7排17座"
}
```

## 根因分析

### 已排除的假设

| 假设                                               | 结论                                                                           |
| -------------------------------------------------- | ------------------------------------------------------------------------------ |
| `getSeatLayout` 只取 `room_seat[0]` 丢弃了其他分区 | ❌ 不成立。经确认 `room_seat` 只有一个元素，所有座位均在 `[0]` 下              |
| 浏览器/Electron HTTP 缓存导致重试无效              | ❌ 不成立。如果真有浏览器级缓存，所有 GET 请求都会受影响，不会只针对这一个接口 |

### 确认根因：金逸服务端数据一致性问题

金逸 `/hall/saleable/` 接口在短时间内多次调用，偶发返回不一致的座位数据——前几次缺少部分座位（如 col 17、18），后续才返回完整列表。属于金逸服务端自身的数据同步延迟或缓存一致性问题，客户端无法从根本上规避。

之前出现的"重新出票就好了"也是因为间隔足够长，服务端数据已同步完成。

## 修复方案

### 已实施：`getTargetSeat` 增加重试机制

应对服务端数据偶发不一致，目标座位数量不匹配时等待服务端数据同步后重试。

**重试策略**：每 2 秒重试一次，最多 6 次（总计最多 12 秒）。

### 修改文件

| 文件                                                  | 修改内容                                  |
| ----------------------------------------------------- | ----------------------------------------- |
| `src/common/autoTicket/buyTicket/jinyi/seatManage.js` | `getTargetSeat` 增加重试逻辑（2s × 6 次） |

### 修改详情

```javascript
// 新增重试配置
const RETRY_DELAY = 2; // 每次间隔 2 秒
const RETRY_MAX = 6; // 最多 6 次

// 目标座位不足时重试查询
for (let i = 0; i < RETRY_MAX; i++) {
  if (targetSeats.length == this.order.ticket_num) break;
  await mockDelay(RETRY_DELAY);
  seatListRes = await this.getSeatLayout(params);
  // ...重新过滤目标座位
}
```

- [ ] 金逸系列正常出票流程（一次成功场景）不受影响

## 回归风险评估

- **低风险**：仅在获取目标座位失败时触发重试，不影响正常出票路径
- 重试时机在锁座之前，不会产生额外锁座或扣费操作
- `getSeatLayout` 方法未做任何改动
