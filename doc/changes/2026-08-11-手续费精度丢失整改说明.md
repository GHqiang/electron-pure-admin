# 手续费精度丢失整改说明

> 日期：2026-08-11
> 状态：**已实施**
> 背景：手续费计算采用 JS 原生浮点乘法（如 `price * feeRate`），存在精度丢失（典型 `31.3 * 0.06 = 1.8780000000000001`）。守兔按 `needInvoice` 分档（1% / 6%）上线后，6% 档位精度问题更易暴露。本次统一将手续费原生乘法改为 `mulDecimal`（基于 decimal.js），保证计算精度。

---

## 1. 问题复现

```js
// 原生乘法（有精度丢失）
31.3 * 0.06       // = 1.8780000000000001
31.3 * 0.01       // = 0.31300000000000006
35.5 * 0.06       // = 2.1300000000000003

// mulDecimal（基于 decimal.js，无精度丢失）
mulDecimal(31.3, 0.06)  // = 1.878
mulDecimal(31.3, 0.01)  // = 0.313
mulDecimal(35.5, 0.06)  // = 2.13
```

精度丢失会导致：手续费多算/少算一分，进而影响真实成本、预计利润、最大卡券成本的判断，可能导致规则误不报价或负利润订单被放行。

---

## 2. 整改原则

- **仅改手续费乘法部分**：只把 `shouxufei = x * feeRate` 形态改为 `mulDecimal(...)`，不动奖励费用、利润、卡券成本等其他计算
- **保持参数语义不变**：`mulDecimal(Number(x || 0), feeRate)` 与原 `Number(x || 0) * feeRate` 在数值上等价（仅消除精度误差）
- **统一三种形态**：
  - `x * feeRate` → `mulDecimal(Number(x || 0), feeRate)`
  - `offer_end_amount * fee_rate` → `mulDecimal(Number(offer_end_amount || 0), fee_rate)`
  - `(x * 100) / 10000`（旧数据 1% 兜底）→ `mulDecimal(Number(x || 0), 0.01)`

## 4. 统一改造方式

所有手续费原生乘法 → `mulDecimal`（`@/utils/utils` 导出，基于 decimal.js）：

```js
// 改前（有精度丢失）
let shouxufei = Number(supplier_end_price || 0) * feeRate;

// 改后
let shouxufei = mulDecimal(Number(supplier_end_price || 0), feeRate);
```

各文件需在 import 块追加 `mulDecimal`：

```js
import { /* ...原有导入 */, mulDecimal } from "@/utils/utils";
```

## 6. 边界与降级

| 场景 | 行为 |
| --- | --- |
| 守兔 `needInvoice=0`（6%） | `mulDecimal(31.3, 0.06) = 1.878`，无精度误差 |
| 守兔 `needInvoice=1`（1%） | `mulDecimal(31.3, 0.01) = 0.313`，无精度误差 |
| 其他平台（1%） | `mulDecimal(price, 0.01)`，无精度误差 |
| 免手续费平台（haha/mahua） | `feeRate=0`，`mulDecimal(x, 0) = 0`，行为不变 |
| 历史报价记录展示（旧数据 fee_rate 为 NULL） | `mulDecimal(offer_end_amount, 0.01)` 兜底，无精度误差 |
