# 出票侧订单源头补全 app_type_code 修复说明

> 日期：2026-08-21
> 状态：已实施（待提交，版本 6.6.42）
> 依据：生产日志实测（5 个订单 L1/L2 对照）定位 + 用户裁定方案（拉单列表源头补全，替代逐点 v3Ready）
> 用途：修复"出票侧订单无 app_type_code → v3Mode 判定异步完成前日志错位（L1 混入 info / L2 明细缺失）"

---

## 一、问题现象（生产实测）

5 个订单（lieren/sheng × sfc_applet，user_id=10，2026-08-21 14:25~14:35）：

1. **异常日志（L1/opera_record）出现非 error 级**：如"订单开始出票"、"单个待出票订单信息"、"获取该影院登录信息返回"、"解锁座位入参"等 info 级；
2. **明细日志（L2）中上述日志缺失**（同 des 在 L2 中不存在）——"异步获取场景日志不全"。

## 二、根因分析（代码 × 生产数据双重验证）

出票侧订单（平台拉单/重出快照）**无 `app_type_code` 字段**（订单/DB 中系列标识字段为 `app_type`）。`logger.init(order)` 时：

- `_applyV3FlagsSync(app_type_code)`：`if (app_type_code)` 不成立 → **同步判定跳过**（localStorage 字典缓存也不生效）；
- 判定完成前（动态 import 毫秒级窗口），新 Logger 实例 `v3Mode=false`：
  - L1 收窄条件 `isSaveIntent && this.v3Mode && ...` 不成立 → infoSave **全量入 L1**；
  - `traceEnabled=false` → **不进 L2 明细**。

对照组：报价侧各队列（LierenOfferQueue 等 12 个）构建订单时**已补** `app_type_code: GET_APP_INFO(app_name)?.app_type_code` → 报价段 L2 明细正常，与生产数据吻合。

## 三、修改内容（用户裁定方案：拉单列表源头补全）

| 文件 | 修改 |
| --- | --- |
| `src/common/platform/fetchers/` 11 个平台拉单器（Lieren/Haha/Mahua/Mangguo/Mayi/PiaoSheng/Shangzhan/Sheng/Shoutu/Yangcong/Yinghuasuan） | 拉单订单转换处补 `app_type_code: GET_APP_INFO(app_name)?.app_type_code`（与报价侧 queues 同款写法），import 补充 `GET_APP_INFO` |
| `src/common/autoTicket/buyTicket/{sfc,ume,lma,h5ume}/orderManage.js` 等 10 处 | `logger.init` 统一改解构传参（`this.order` / `orderInfo?.app_type_code` 补传） |
| `src/common/core/BaseTicketQueue.js` | `handleNewOrder` 入口保留兜底补全：`if (!order.app_type_code) order.app_type_code = GET_APP_INFO(order.app_name \|\| order.appName)?.app_type_code`（覆盖再次出票快照等遗漏路径，防御性）；移除 handleNewOrder/重复执行分支的 v3Ready 调用 |
| `src/common/core/BaseOrderFetcher.js` | `logOrderEvent` 恢复 order 缺失兜底：`logger.init(order ?? { plat_name: this.platName })`（防解构崩溃）；移除 v3Ready 调用 |
| `src/common/logger.js` | **移除 `v3Ready()` 方法与 `_applyV3Flags` 异步判定、`_v3FlagsPromise` 调用**——仅保留 `_applyV3FlagsSync` 同步判定（订单 `app_type_code` + localStorage 字典缓存），v3Mode/traceEnabled 判定全部同步完成，无竞态窗口 |

补全后：订单从拉单起即带 `app_type_code` → `logger.init(order)` 同步判定（`_applyV3FlagsSync`，localStorage 字典缓存）立即生效，type 1/2/3 所有 logger（队列级/每单新建/异步轮询独立实例）零改动受益；v3Ready 与异步判定机制整体移除。

## 五、回归风险

- **低**：补全仅新增订单字段（`app_type_code`），不改变业务主流程；`GET_APP_INFO` 基于 allAppList 全量影线配置（业务运行时必然已加载），反查失败时订单不带该字段、logger 判定回退（v3Mode=false 全量入 L1，不丢日志）
- 已知行为：localStorage 无字典缓存的首启场景，同步判定跳过 → 日志按旧逻辑全量入 L1（暂不分级），字典缓存写入后自动恢复
