# 三张表增加 fee_rate（手续费率）字段整改说明

> 日期：2026-08-11
> 状态：**已实施**
> 背景：守兔手续费已按 `needInvoice` 分档（1→1%，0→6%），但报价记录表/未报价记录表/中标价同步表均未存储手续费率，历史报价记录展示组件 `HistoryOfferRecord.vue` 仍按硬编码 1% 重新计算，导致 `needInvoice=0` 的守兔订单利润展示偏高（少扣 5 个点）。本次为三张表增加 `fee_rate` 字段，写入时落库，展示时直接读取，保证展示与实际一致。

---

## 1. 字段设计

| 项 | 内容 |
| --- | --- |
| 字段名 | `fee_rate` |
| 类型 | `DECIMAL(5,4)` |
| 含义 | 手续费率（0~1），如 0.0100=1%、0.0600=6% |
| NULL | 允许 NULL（旧数据无此字段，展示时按 1% 兜底，`NO_FEE_PLAT_LIST` 平台按 0 兜底） |
| 取值来源 | 前端写入时调 `getPlatFeeRate(order)` 算出费率落库 |

---

## 2. 三张表 DDL 变更

### 2.1 ALTER TABLE SQL

```sql
-- 报价记录表
ALTER TABLE offer_record ADD COLUMN fee_rate DECIMAL(5,4) DEFAULT NULL COMMENT '手续费率(0~1,如0.01=1%,0.06=6%)' AFTER rewards;

-- 未报价记录表
ALTER TABLE offer_record_fail ADD COLUMN fee_rate DECIMAL(5,4) DEFAULT NULL COMMENT '手续费率(0~1,如0.01=1%,0.06=6%)' AFTER rewards;

-- 中标价同步表
ALTER TABLE sync_offer_record ADD COLUMN fee_rate DECIMAL(5,4) DEFAULT NULL COMMENT '手续费率(0~1,如0.01=1%,0.06=6%)' AFTER price_spread;
```

### 2.2 doc/表ddl.md 同步更新

三张表的建表语句各加 `fee_rate` 列定义。

## 3. 后端代码变更

### 3.1 offer_record / offer_record_fail — 无需改动

`auto-ticket-service/api/offerRecord.js` 的 `addRecordData`（L356-384）采用**动态拼 key**方式：`Object.keys(obj)` 遍历字段拼 SQL。前端 `serOrderInfo` 新增 `fee_rate` 字段后，后端自动写入，无需改动。

### 3.2 sync_offer_record — 必须改 3 处

`auto-ticket-service/api/offerRecord.js` 的 `syncOfferRecord`（L521-621）采用**固定字段列表**，需在 3 处同步加入 `fee_rate`：

| INSERT 字段列表 | L548-554 | 加 `fee_rate` |

## 5. 展示侧变更

### 5.1 HistoryOfferRecord.vue — formatCostPrice / formatProfit（L567-608）

**当前逻辑**：硬编码 1% 算手续费，`NO_FEE_PLAT_LIST` 命中置 0。

**改为**：优先读记录的 `fee_rate` 字段；`fee_rate` 为 NULL（旧数据）时按 1% 兜底，`NO_FEE_PLAT_LIST` 平台按 0 兜底。

```js
import { NO_FEE_PLAT_LIST } from "@/common/constant";
import { mulDecimal } from "@/utils/utils";

// formatCostPrice / formatProfit 内手续费计算改为：
let shouxufei;
if (fee_rate != null) {
  // 新数据：直接用存的费率
  shouxufei = mulDecimal(Number(offer_end_amount || 0), fee_rate);
} else {
  // 旧数据兜底：默认 1%，NO_FEE_PLAT_LIST 平台为 0
  shouxufei = mulDecimal(Number(offer_end_amount || 0), 0.01);
  if (NO_FEE_PLAT_LIST.includes(plat_name)) {
    shouxufei = 0;
  }
}
```

`formatCostPrice` 和 `formatProfit` 的参数解构各加 `fee_rate` 字段。

### 5.2 不改的项

- 报价/出票环节的手续费计算 — 已走 `getPlatFeeRate`，不改

> 注：`MahuaAdapter.js` / `PiaoShengAdapter.js` 的 `_getProfit` 原表述为"不改"，理由是不影响守兔。后续精度改造（详见 `2026-08-11-手续费精度丢失整改说明.md`）从精度一致性角度将其 `_getProfit` 内的手续费原生乘法一并改为 `mulDecimal`，并将费率来源统一为 `getPlatFeeRate(order)`（行为与原逻辑等价：mahua→0、piaosheng→1%），本节原表述已据此修正。

## 7. 边界与降级

| 场景 | 行为 |
| --- | --- |
| 新数据（有 fee_rate） | 展示时直接用 `offer_end_amount * fee_rate` |
| 旧数据（fee_rate 为 NULL） | 兜底 1%，`NO_FEE_PLAT_LIST` 平台兜底 0% |
| `fee_rate` 为 0 | 手续费为 0（haha/mahua 平台） |
| 守兔 `needInvoice=1` | `fee_rate=0.01`，展示 1% |
| 守兔 `needInvoice=0` | `fee_rate=0.06`，展示 6% |
| sync_offer_record 同步 | 从 offer_record 复制 fee_rate，保持一致 |

5. **深入自查**：import 路径、order 参数可访问性、后端字段顺序一致性、SQL AFTER 子句与 DDL 一致性、旧数据兜底逻辑——全部通过。
