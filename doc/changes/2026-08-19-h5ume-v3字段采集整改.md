## 二、报价侧（offerManage.js）

### calcSteps 拼装段（getEndMatchOfferRule + getMinAmountOfferRule）

```
初始匹配命中N条
→ 券库存过滤剩N条               （fixedAmountRuleList 券库存 + 日出票券数过滤后）
→ 会员日规则命中(X元)           （onlyMemberDayRuleList 命中即返回）
→ 会员价加价命中(X元)           （memberOfferAmount 计算完成）
→ 定价策略段                     （仅固定价 / 仅会员价 / 固定 vs 会员取低，对照 chenxing 模式）
```

- h5ume 无独立 filterByFilmType 方法：电影格式校验内联在 getMovieInfo（不匹配时 filmTypeCheckFail 直接 return null，无剩余条数可统计），故 getEndMatchOfferRule 只 push 初始匹配段，与"照该系列实际过滤步骤"一致
- `getMinAmountOfferRule(ruleList, order, movieInfo, calcSteps = [])` 签名加 `calcSteps = []`（默认值兼容其它调用点）
- 返回前：`const endRuleCopy = JSON.parse(JSON.stringify(endRule)); endRuleCopy.calc_path = calcSteps.join("→"); endRuleCopy.hit_rule_name = endRule.ruleName || "";`（替换原 `endRule = JSON.parse(JSON.stringify(endRule)); return endRule;`）
- `calc_path`/`hit_rule_name` 由 BaseOfferQueue serOrderInfo 收口（截断 500）入库，本文件只负责挂到 offerRule

- `cardNum`/`useQuan`/`payAmount` 均为函数级作用域（useQuanOrCard 解构 / 第 686 行声明），return 处可直接访问，无需提升
