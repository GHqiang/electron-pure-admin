# 重新出票订单快照内存缓存修复说明

> 日期：2026-08-21
> 状态：已实施（待提交，版本 6.6.45）
> 用途：解决"出票失败后第一时间点重新出票查不到日志、无法还原订单"的问题

---

## 一、问题现象

出票失败后立即点"重新出票"按钮，提示"未找到该订单的出票快照，无法重新出票"。

## 二、根因分析

1. 重新出票（`againTicket`）需要还原完整出票订单（supplierCode/seats/lockseat 等），来源是"自动出票队列获取到新的待出票订单"快照日志；
2. v3Mode 生效后该快照（infoSave）不入 L1（opera_record），只落 L2（trace 文件）——againTicket 走 L1 查不到 → L2 兜底；
3. **L2 上传是 fire-and-forget + 全局串行链**（`logUpload` 入队即返回，出票流程不等待）——失败瞬间日志可能还在客户端缓冲/上传中，服务器文件尚未写入 → L2 查询必然查不到；
4. 本质：**即时操作（重新出票）依赖了异步日志链路**。

## 三、修复内容（内存快照优先 + 日志查询降级兜底）

| 文件 | 修改 |
| --- | --- |
| `src/common/core/BaseTicketQueue.js` | `handleNewOrder` 将出票订单（补全 app_type_code 后）写入 `window.__ticketOrderSnapshots`（Map，上限 200 单，超出删最旧，防内存膨胀） |
| `src/components/HistoryTicketRecord.vue` | `againTicket` 优先取 `window.__ticketOrderSnapshots.get(order_number)`（零网络延迟）；快照缺失（客户端重启等）降级走原 L1→L2 日志查询链 |

修复后链路：出票失败 → 立即点重新出票 → 内存快照直接还原订单（毫秒级）→ dispatch 重新出票；客户端重启后快照丢失 → 日志查询兜底（日志此时大概率已落盘）。

## 四、验证

- `node --check` BaseTicketQueue.js 通过；eslint HistoryTicketRecord.vue 无错误；jest（ticketQueueLierenRuleCheck / rootErrCache）通过
- 逻辑核对：快照为 handleNewOrder 的完整出票订单对象（含 app_type_code）；重复出票时快照被覆盖为最新版本（isAgain 语义一致）；Map 引用随出票流程更新（_ticketEnqueueAt/_cachedOfferRule 等）

## 五、回归风险

- **低**：内存快照仅新增 window 级 Map，不影响出票主流程；200 单上限防内存膨胀；降级路径保持原行为
- 说明：本修复解决"重新出票还原订单"；L2 日志上传本身的延迟（串行链 + 网络 RTT）仍在，人工排查日志时如遇未落盘可稍后重查
