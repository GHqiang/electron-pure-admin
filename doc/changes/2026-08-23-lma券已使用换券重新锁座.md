# LMA「券已使用 → 换券重新锁座」设计、实现与变更记录

日期：2026-08-23

## 一、背景与根因

lma（卢米埃）账号被多个订单共用，先后/并发出票时，后一单拉券时前一单刚消耗的券还没写入 `ticket_record`（`queryUsedQuanList` 查的是 ticket_record 表，只有成功出票才落库，存在竞态窗口）→ 选到已用券 → LMA 锁座返回 `{"data":0,"status":false,"code":"O","alert":{"title":"券已使用,锁座失败!","msg":"券已使用，锁座失败!"}}` → 目前直接转单/手动处理。

## 二、方案设计

### 触发条件

`buyTicket.js` 中 `lockseatByApp` 抛错后，先检查错误文本是否命中「券已使用」类关键词（模块级常量数组 `QUAN_USED_ERROR_KEYS`，初始 `["券已使用"]`，后续可扩展）。命中才走换券重试，其他错误保持现有分支不变。

### 换券重试循环（新增方法 `retryLockSeatWithQuanSwap`）

1. **全量替换**：LMA 不告知具体哪张券坏了，从备选券池整批取 `ticket_num` 张替换当前券 → 重新 `lockseatByApp`
2. **备选池不足** → 重新从 lma 账号拉最新券列表（复用 `continuousGetQuanForUse`，按过期时间排序，**排除本订单已试过的券码**，存于方法内局部 `Set`，不写库）整体替换补池；补完仍不足 `ticket_num` → 停止
3. **上限**：最多 2 次全量替换（`QUAN_SWAP_RETRY_LIMIT`，对齐 h5ume `COUPON_RETRY_LIMIT`），每次间隔 1 秒（`QUAN_SWAP_RETRY_DELAY`）；换券后仍报"券已使用"则继续换下一批，直到上限
4. 重试内遇到非"券已使用"错误（如网络异常）→ 立即停止，按现有分支处理

### 成功路径

用最终生效的 `quan_code` 继续原有流程（价格计算、购买等），`quan_code` 变量用换券后的新值（格式同为 `[{code}]` JSON，兼容后续快照/入库解析）。

### 耗尽兜底

换券重试耗尽 → **尝试换号**（`currentParamsInx++` 重跑 `oneClickBuyTicket`，与现有"用券异常走换号"分支一致，`otherParams` 结构一致）；已是最后一个账号 → 走现有转单逻辑（保留申请换座判定）。

### 备选券池来源

`useQuanHandle`（cardQuanManage.js）改造：现在拉全量券排序后只取前 `ticket_num` 张，其余丢弃；改为同时返回 `remainQuanList`（剩余券，元素 `{code}`，已按过期时间排序）作为备选池，**零额外请求**。券面额相同（同一 `quan_flag`），换券不重算利润/手续费。

## 三、关键决策记录

- **实施范围**：仅 lma 系列；其他系列同类场景记录到待优化文档，暂不修改
- **券源策略**：备选池优先（首次拉全量券的剩余部分，零额外请求），不足时重新拉账号最新券列表
- **失败券处理**：仅本次订单内存排除已试券码，不写数据库
- **耗尽兜底**：尝试换号，最后账号才转单
- **连续相同错误检测**：不单独实现——"券已使用"本身是同一错误 key，换券后仍报相同错误是并发场景常态（新券可能也被并发消耗），靠 2 次上限约束即可

## 五、实现过程（TDD）

### Task 1: useQuanHandle 返回备选券池 remainQuanList

1. 新建测试文件 `src/common/tests/lmaQuanSwapRetry.test.js`（mock utils/platTokens/dictTable/constant/common index/sv-api/offerHelper/logger/usesMachineBaseFun/commonQuanStock/cardBalanceSync/BaseBuyTicket），写 useQuanHandle 用例：5 张券、`usedQuanList` 命中 C3、`ticket_num=2` → 断言 `quan_code` 为前 2 张（C5、C4，按过期时间升序）、`remainQuanList` 为剩余 2 张（C2、C1）

4. 绿：测试通过

### Task 2: 锁座"券已使用"检测 + 换券重新锁座 + 耗尽换号

1. 追加 5 个 `retryLockSeatWithQuanSwap` 用例（通过 `Object.create(LmaBuyTicket.prototype)` 构造实例并挂 mock 依赖，绕开构造函数）：
   - 备选池充足换券成功（第 1 次锁座报券已使用 → 换下一批 → 成功）
   - 备选池不足重拉成功（重拉列表过滤已试券码，按过期时间升序取券）
   - 重拉后仍不足票数 → 返回 error 且不锁座
   - 连续券已使用达上限（2 次）→ 返回 error
   - 非券已使用错误立即停止（只锁座 1 次）
2. 红：`retryLockSeatWithQuanSwap is not a function`
3. 实现（见"四、修改文件清单"）：常量、解构 `_remainQuanList`、catch 分支（申请换座判定 → 券已使用检测 → 换券重试 → 成功继续/失败换号/转单兜底）、新方法
4. 绿：6 个用例全部通过

## 七、回归风险评估

- 改动集中在 lma 锁座失败分支：不命中"券已使用"时行为完全不变（申请换座判定在前，转单兜底保留）
- 换券成功路径与正常出票共用后续代码（价格计算、购买、取票码上传），无新增独立链路
- useQuanHandle 仅新增返回值字段，原 quan_code/quanStock 语义不变，报价侧不受影响
- 换号兜底复用现有"用券异常走换号"分支（otherParams 结构一致），递归深度受登录账号数限制
- 风险点：若 LMA 侧"券已使用"为误报（券实际未消耗），换券会多消耗备选券；
  受 2 次上限约束，且备选池/重拉均为真实可用券，风险可控
- 上线后观察日志"换券重试:第N次使用新券重新锁座"/"券已使用换券耗尽，走换号"统计命中率；
  若"券已使用"变体文案增多，扩展 `QUAN_USED_ERROR_KEYS` 即可
