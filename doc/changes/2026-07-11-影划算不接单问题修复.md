# 影划算平台偶发不接单问题修复

## 修改文件清单

| 文件                                                      | 改动说明                       |
| --------------------------------------------------------- | ------------------------------ |
| `src/common/platform/fetchers/YinghuasuanOrderFetcher.js` | 增加接单结果记录、确认失败日志 |

## 问题背景

生产环境偶发影划算平台订单到达后未被确认接单，导致订单进入待出票列表后因 `order_number` 为空被过滤丢弃。

## 根因分析

影划算订单处理链路为：获取待确认列表 → 匹配报价记录 → 调用确认接口。链路中两处可能偶发失败：

1. **`getOfferList()` 查询 SV 报价记录**：网络抖动或 SV 服务异常时静默返回 `[]`，导致后续 `order_id === in_id` 匹配全量失败，本轮所有待确认订单被跳过。

2. **`confirmOrder()` 调用平台确认接口**：平台 API 偶发超时或返回异常时只记录日志不重试，单次失败后该订单即被丢弃。

此外，原有代码在确认链路的各个环节均无诊断日志，线上问题难以定位具体断裂点。

## 核心变更

### 1. 接单成功时记录平台原始返回

```diff
  this.confirmOrderList.push({
    ...item.demands,
    in_id: item.in_id,
    bro_id: item.bro_id,
    quote_price: item.quote_price,
    offer_order_number: offerRecord?.order_number,
+   confirmOrderRes: res // 接单结果
  });
```

`confirmOrderRes` 随后在 `fetchOrders()` 中透传到订单对象的 `confirmOrderRes` 字段，最终出现在"影划算新的待出票订单"日志中，便于排查接单成功时的平台返回内容。

### 2. 接单失败时上报诊断日志

```diff
  if (!res?.error) {
    // ... 成功逻辑
  }
+ else {
+   logUpload(
+     { plat_name: "yinghuasuan", app_name: "", order_number: "", type: 2 },
+     [{
+       opera_time: getCurrentTime(),
+       des: "影划算确认接单异常",
+       level: "error",
+       info: { in_id: item.in_id, confirmOrderRes: res }
+     }]
+   );
+ }
```

确认接口返回 `res?.error` 时，通过 `logUpload()` 直接上传一条 `"影划算确认接单异常"` 日志，包含平台订单 `in_id` 和平台原始返回，便于线上定位接单失败的具体原因。

> **注意**：此处使用 `logUpload()` 工具函数直接上传，而非 `this.logger.xxxSave()`，因为 Logger 实例的 `*Save` 方法仅缓存到内存数组，需显式调用 `logUpload()` 才会触发实际上传，而当前流程中无该调用点。`logUpload()` 工具函数则即时上传。

## 测试结果

- 语法检查通过，无 eslint/ts 报错

## 回归风险评估

- **低风险**：改动限于影划算平台的 `YinghuasuanOrderFetcher.js`，不影响其他平台
- `confirmOrderRes` 仅新增字段记录，不改变原有逻辑
- 确认失败日志为增量新增的 `else` 分支，不改变成功路径
- `logUpload()` 为异步上传，失败不影响主流程
