# 洋葱平台手续费率由 1% 调整为 2%（实施记录）

> 日期：2026-10-10
> 状态：**已实施（2026-10-10）**，代码已落地，未提交
> 需求：洋葱平台报价计算所用手续费点数，由百分之一（1%）改为百分之二（2%）
> 确认口径：**仅洋葱改为 2%，其它平台保持 1%**；报价记录列表对旧数据的 1% 兜底**不调整**（用户 2026-10-10 确认）

## 1. 检索结论：手续费点数只有一处来源

术前全仓检索（`手续费|feeRate|poundage|serviceFee`、`0.01`、`/ 10000`、`getPlatFeeRate`）确认：**洋葱平台报价手续费没有独立配置**，与报价/出票链路共用唯一费率函数 `getPlatFeeRate(order)`（`src/common/autoTicket/buyTicket/common/offerHelper.js`）。

| 平台 | 调整前费率 | 依据 |
| --- | --- | --- |
| 哈哈 haha / 麻花 mahua | 0% | `NO_FEE_PLAT_LIST`（`src/common/constant.js:26`） |
| 守兔 shoutu | 1%（`needInvoice=1`）/ 6%（0 或缺失） | `getPlatFeeRate` 守兔分支 |
| **洋葱 yangcong** | **1%（默认分支）** | 同上 |
| 猎人 / 省APP / 芒果 / 蚂蚁 / 影划算 / 票圣等 | 1%（默认分支） | 同上 |

三个容易误判的点，均已逐个排除：

1. **`platManage.js:888` 的「洋葱转单是原价的百分之三」是转单手续费**（`transfer_fee`，固定 3 个点），与报价手续费是两回事，本次不动；
2. **`YangcongAdapter.js` 无独立手续费/利润计算**（仅 `MahuaAdapter` / `PiaoShengAdapter` 的 `_getProfit` 内有一处，且都调用 `getPlatFeeRate`），洋葱链路无旁路；
3. **各系列 `cardQuanManage` / `buyTicket` 里的 `/ 10000` 全是奖励金公式**（`offer_end_amount * 100 * rewards / 10000`），不是手续费；手续费处均已为 `mulDecimal(x, getPlatFeeRate(this.order))`。

## 3. 核心变更说明

`src/common/autoTicket/buyTicket/common/offerHelper.js:162-174`：

```js
export function getPlatFeeRate(order) {
  const plat_name = order?.plat_name;
  // 免手续费平台优先
  if (NO_FEE_PLAT_LIST.includes(plat_name)) return 0;
  // 守兔按 needInvoice 分档：1→1%，0/缺失→6%（保守，避免少收）
  if (plat_name === "shoutu") {
    return Number(order?.needInvoice) === 1 ? 0.01 : 0.06;
  }
  // 洋葱 2%
  if (plat_name === "yangcong") return 0.02;   // ← 本次新增
  // 默认 1%
  return 0.01;
}
```

放置在免手续费名单与守兔分支**之后**、默认分支**之前**：洋葱不在免手续费名单内，与守兔分支互斥，顺序不影响结果，仅保持「特例在前、默认在后」的既有写法。

### 3.1 一处生效、全链路覆盖

改这一个函数后，下列环节对洋葱订单一并生效（均调用 `getPlatFeeRate`，无需逐个改）：

| 环节 | 位置 | 影响 |
| --- | --- | --- |
| 报价计算（模式 A） | `common/offerHelper.js` 的 `calcOfferCostProfitParts` | 手续费、`pay_cost_price`、真实成本、预计利润、`maxCostPrice`（券过滤） |
| 报价计算（模式 B，内联） | `sfc`/`ume`/`lma`/`jinyi`/`chenxing`/`fenghuang`/`h5ume`/`wanda` 的 `offerManage.js` | 最终报价构成日志与利润判断 |
| 出票复核（用券/用卡） | 各系列 `cardQuanManage.js`、`lma/buyTicket.js` | 用券/用卡利润复核与「无利润转单」判定 |
| 费率落库 | `BaseOfferQueue.js:1245`、`BaseTicketQueue.js:521` 的 `fee_rate` | 新报价记录 `fee_rate = 0.0200` |
| 记录展示 | `HistoryOfferRecord.vue` 读 `fee_rate` | 新数据自动按 2% 展示，无需改代码 |

### 3.2 明确不改的两处

1. **`HistoryOfferRecord.vue:796/823` 的 1% 兜底**：仅用于 `fee_rate` 为 `NULL` 的**历史**记录，那些记录当时就是按 1% 计费的，保持 1% 才是真实成本；新数据已落库费率，自动走新值（用户已确认）；
2. **`MahuaAdapter.js:59` / `PiaoShengAdapter.js:59` 的注释**（「免手续费名单 + 默认 1%」）：麻花为 0、票圣为 1%，默认值与本次改动无关，按「只改与需求直接相关的行」原则不动。
