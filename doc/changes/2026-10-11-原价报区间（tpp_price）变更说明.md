## 1. 需求

报价前按订单原价（`tpp_price`）过滤规则：**订单原价落在配置区间内才参与报价，不在区间内则剔除该规则**；未配置 = 不限制 = 照报。原价字段统一用 `tpp_price`。

相对上一版「原价不报」（多条表达式、命中即不报）的变化：**语义方向翻转**（命中→剔除 改为 不在区间→剔除）、**配置收敛**（去掉分号多条与 6 种操作符，只保留一个闭区间）、**列改名**（`noOfferTppRule` → `offerTppRange`）。

## 3. 核心变更说明

1. **数据模型**：`rule_record.noOfferTppRule` 改名为 `offerTppRange VARCHAR(64) NULL`。旧列已投产且**从未配置数据**，改名安全、无需迁移。`NULL`/空串 = 未配置 = 不限制，存量规则行为完全不变。
2. **存储格式**：单字符串 `下限-上限`，闭区间含端点；端点可留空：下限空 = 0，上限空 = 正无穷。`50-80`=[50,80]、`50-`=[50,+∞)、`-80`=[0,80]、`-`=[0,+∞)（等价"不限制"）。
3. **过滤语义翻转**：原「命中条件即剔除」改为「原价不在区间内才剔除」。生效点仍是 `offerRuleMatch`（`src/utils/utils.js`）**末尾**（会员日过滤之后），只影响"本来能匹配到规则"的订单，**不改变既有"按城市/影院/影厅/座位数筛选为空"的统计口径**，覆盖全部 8 个影线系列。
4. **未配置即放行**：过滤层第一个判断 `if (!item.offerTppRange) return true`，存量规则零影响。
5. **边界处理**：`tpp_price` 为空/非数值/≤0 → **放行（照报，不写日志）**（避免字段缺失导致大面积不报；`info` 日志**仅在"原价不在区间内、剔除该规则"时**写）；区间配置非法（`80-30`/`abc`）→ **放行 + `errorSave`**（不因配置错误停报，保存时前端已阻断）。
6. **平台报价规则跳过**：已同步猎人平台 + 固定价 + 字典开关 + 时段内的规则由平台报价、本地不参与算价，过滤跳过（判定 `isPlatQuotedRule` 与报价守卫共用，**含时段条件**）。该实数逻辑与上一版一致，本轮不改动 `platQuoteRule.js` / `BaseOfferPrice.js`。
7. **失败原因**：编号沿用 **15**（`err_type` 尚无历史数据），文案与正则改为 `按原价区间筛选后，报价规则为空`；枚举名 `15: "原价不符"` 保留。前端 `HistoryOfferRecord.vue` 遍历枚举，**无需改动**。
8. **配置 UI**：规则弹框「原价报区间」改为两个数字输入（下限、上限）+ 中间 `-`；`formData.offerTppRange` 是唯一存储，`rangeMin/rangeMax` 是其可视化视图（`syncOfferTppRangeStr` UI→存储、`fillOfferTppRangeFromStr` 存储→UI）。去掉下拉 6 操作符、表达式输入框与增删按钮。
9. **列表回显**：`报价/加价金额` 列 B钱包徽标下方回显 `原价报区间:原价50~80`（单边显示 `原价≥50` / `原价≤80`）；未配置不显示。
10. **保存兜底（缺列兜底泛化沿用）**：`NEW_RULE_COLUMNS` 中该列元数据改为 `{ column: "offerTppRange", label: "原价报区间", isUnknown: isUnknownOfferTppRangeError }`；命中缺列时剔除该字段重试并提示「rule_record 缺少 offerTppRange 列，本次保存未包含原价报区间，请运维执行 DDL 后重新保存」。泛化函数 `saveRuleRecordWithNewColumnFallback(request, params, columns)` 本体不变。
11. **出票链路不改**：出票按已选定的规则 id 取规则，不做二次过滤；规则变更不追溯已出票订单。
