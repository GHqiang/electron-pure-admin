# 异步轮询取票码成功后利润补全修复

**日期**: 2026-07-11

## 问题描述

SFC、UME、金逸、辰星等多个影院系列存在系统延迟后轮询获取取票码成功，但保存出票记录时利润为空的问题。

## 根因分析

### 场景1：重新出票 + 异步轮询

1. 订单失败 → 用户点击重新出票 → 支付成功
2. 取票码未就绪（系统延迟）→ 进入异步轮询
3. `saveTicketRecord` 的 `isAgain` 失败分支（`submitRes` 为空），`updateObj` 中**没有 `profit`**，重新出票计算出的利润被丢弃
4. 异步轮询成功后 `submitQrcode` 调用 `updateTicketRecord`，`updateObj` 中**同样没有 `profit`**
5. 最终出票记录 `order_status=1`，但利润丢失

### 场景2：正常出票 + 异步轮询

1. 正常出票 → 支付成功 → 取票码未就绪
2. 主流程 `saveTicketRecord` 保存了 `profit` 和 `order_status=2`
3. 异步轮询成功后 `submitQrcode` → `updateTicketRecord` → `updateObj` 只有 `qrcode`、`order_status`、`err_msg`，**没有 `profit`**
4. 主流程保存的 `profit` 虽然理论上被保留（后端 UPDATE 只更新指定列），但缺乏防御性——如果主流程保存失败或先被覆盖，利润就无法恢复

## 修复方案

### 修复1：`BaseTicketQueue.js` — 重新出票失败分支补利润

`saveTicketRecord` 中 `isAgain` 且 `submitRes` 为空时，`updateObj` 加入 `profit`（有值时才传）。

### 修复2：全系列 `orderManage.js` — 异步轮询更新补利润

在 `asyncFetchQrcodeSubmit` → `submitQrcode` 链路中传递 `profit`，异步更新 `updateTicketRecord` 时补上 `profit` 字段（有值时才传）。

### 修复3：全系列 `buyTicket.js` — 调用链传入 profit

`oneClickBuyTicket` 中调用 `getQrcodeUploadByPlat` / `lastHandle` 时传入 `profit` 参数。

### 有条件更新策略

使用 `...(profit ? { profit } : {})` 展开语法：

- `profit` 有值 → 更新到数据库
- `profit` 无值（0、空字符串、undefined）→ 不传，保留数据库原值

## 代码变更要点

### 方法签名变更

各系列 `orderManage.js` 中以下方法新增 `profit` 参数：

- `getQrcodeUploadByPlat()` / `lastHandle()`
- `asyncFetchQrcodeSubmit()`
- `submitQrcode()`

### updateObj 变更模式

```javascript
// 修改前
updateObj: {
    qrcode,
    order_status: "1",
    err_msg: "系统延迟后轮询获取提交取票码成功"
}

// 修改后
updateObj: {
    qrcode,
    order_status: "1",
    err_msg: "系统延迟后轮询获取提交取票码成功",
    ...(profit ? { profit } : {})
}
```

### BaseTicketQueue 变更

```javascript
// 修改前
updateObj: { order_status: 2, err_msg: "重新出票失败" }

// 修改后
updateObj: {
    order_status: 2,
    err_msg: "重新出票失败",
    ...(res?.profit ? { profit: res.profit } : {})
}
```

## 测试建议

1. **正常出票 + 系统延迟**：模拟影院 API 延迟返回取票码，验证异步轮询成功后利润是否正确写入
2. **重新出票 + 系统延迟**：先触发订单失败，点击重新出票，模拟延迟，验证利润是否正确
3. **利润为 0 的场景**：验证用券出票利润为 0 时，不会误覆盖数据库已有利润值
4. **回归测试**：正常出票（无延迟）流程不受影响

## 回归风险评估

- **低风险**：所有修改均为增量添加参数，不影响现有调用链
- `updateObj` 使用展开语法有条件添加 `profit`，无值时不影响数据库已有记录
- 方法签名新增的参数均为末尾追加，现有调用方不受影响（JS 中多余参数被忽略）
