## 二、核心变更说明

### 1. 报价侧（offerManage.js）

- `getEndMatchOfferRule`：规则匹配后 `const calcSteps = [\`初始匹配命中${matchRuleList?.length || 0}条\`]`；把 calcSteps 传给 `getMinAmountOfferRule`（签名加 `calcSteps = []` 第 4 参）；返回前 `endRule.calc_path = calcSteps.join("→")`、`endRule.hit_rule_name = endRule.ruleName || ""`（挂到 offerRule 上，由 BaseOfferQueue serOrderInfo 收口截断 500 入库）。
- `getMinAmountOfferRule` 内关键节点 push：
  - 会员日规则命中（`会员日规则命中(N元)`）
  - 固定报价规则按电影格式过滤后（`电影格式过滤剩N条`）——lma 的电影格式校验在 getEndMatchOfferRule 仅为"不匹配即不报"检查（不缩减列表），真正的列表过滤发生在 getMinAmountOfferRule 的 fixedAmountRuleList 上，故该段在此拼装
  - 券库存/日限量过滤后（`券库存过滤剩N条`，含 appQuanTypeList 为空置空分支）
  - 会员预计报价算出后（`会员价加价命中(N元)`）
  - 定价策略段（lma 为多出口 return，无法像 jinyi 单点拼装，按实际决策点分别 push）：
    - 会员价失败/无会员加价规则回退固定价 → `仅固定价X`
    - 无固定价规则 → `仅会员价X`
    - 两者都有 → `固定价A vs 会员价B，取固定/会员`

### 2. 出票侧（buyTicket.js）

- `let cardBalance = null;` 提升到外层（`if (card_id)` 块前），块内 `cardBalance = oldBalance;`（oldBalance 为原代码已解析的支付前卡余额，纯复用不新增计算）。
- 成功路径 return 前采集：
  - `useQuanList = quan_code ? JSON.parse(quan_code) : []`（lma 的 quan_code 为已用券码数组 JSON 字符串，元素仅含 `code`）
  - `couponsSnapshot = useQuanList.slice(0, 10).map(item => ({ couponCode: item.code }))`
  - `usePath = this.buildTicketUsePath({ offer_type, useQuan: useQuanList, cardNum, cardBalance, paymentAmount, currentParamsInx })`
- return 对象新增：`paymentAmount: paymentAmount ?? null`、`cardBalance: cardBalance ?? null`、`coupons: couponsSnapshot`、`usePath`（数值列传 null 而非 ""，避免 MySQL 严格模式 ERROR 1366）。
- 复制 jinyi 的 `buildTicketUsePath` 方法（方法体照抄，含换号N次/用券N张/卡尾号付券手续费/用卡尾号+支付前余额+实付 三段拼接）。

## 三、与 jinyi 样板的结构差异及对应处理

| 差异 | 处理 |
|------|------|
| lma 无 `useQuan` 数组（jinyi 由 useQuanOrCard 返回），lma 的 `useQuanHandle` 返回 `{ quan_code: 券码数组JSON串, quanStock }` | couponsSnapshot/usePath 从 `JSON.parse(quan_code)` 结果取（元素仅含 code，无 couponType/couponName，coupons 只挂 couponCode） |
| lma 无 `cardBalance` 变量，仅有 `card_balance`（"￥36.6" 字符串）与 if 块内 `oldBalance`（数字） | 照 jinyi 模式提升 `let cardBalance = null;`，块内复用 oldBalance 赋值 |
| `paymentAmount` 现状 | **已是元（数字）**：buyTicket.js:600 `Number(priceInfo.price_str?.replace("￥", "") || 0)`，直接用现有值，不新增转换 |
| `getMinAmountOfferRule` 为多出口 return（会员日直返/会员价失败回退/无固定价直返/末尾对比），非 jinyi 单出口 comparePricingStrategies | 定价策略段在**各决策点分别 push**（仅固定价×3 / 仅会员价×1 / 固定 vs 会员取低×1），保证 calc_path 反映真实路径 |
| 电影格式过滤位置不同 | lma 的格式过滤在 getMinAmountOfferRule 的 fixedAmountRuleList 上（getEndMatchOfferRule 内仅为校验检查），"电影格式过滤剩N条" 在过滤处拼装 |

## 五、回归风险评估

| 风险 | 等级 | 控制 |
|------|------|------|
| 未执行 DDL 即部署 → 动态 INSERT Unknown column | 高 | DDL 脚本（v3-log-columns-2026-08-18.sql）需先行；addRecordData 失败被 catch 不阻塞主流程 |
| 新字段 undefined → mysql 绑定参数报错 | 高 | 收口层 `?? null`/`?? ""` 兜底；lma return 数值列显式 `?? null`（`""` 会绕过 ??，两层都要） |
| `JSON.parse(quan_code)` 抛错影响出票成功返回 | 低 | quan_code 恒为 useQuanHandle 内 `JSON.stringify` 产物（合法 JSON 数组串）；空串/undefined 用 `quan_code ? ... : []` 守卫 |
| calc_path 拼装引用不存在字段 | 低 | 全部取值点均有值保证（onlyMemberDayRuleList[0]、minAddAmountRule.memberOfferAmount 等均在对应赋值/过滤后）；仅固定价段用 `?.` 保护 |
| 基类/其他系列影响 | 无 | 公共文件未改动；其他系列不传新字段 → 收口默认值，INSERT 行为不变 |
