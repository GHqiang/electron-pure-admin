# 金逸系列实体券验券接入、支付方式与卡处理对齐

- 日期：2026-10-30（2026-10-30 复查补充多券与卡处理）
- 触发：订单 `2026102909440878793`（lieren / `subojinsong` / 团购券）出票失败
  —— 算价返回 `{"ret":0,"sub":4004,"msg":"获取兑换券验券异常，请联系影院"}`
- 依据：手工出票 HAR 抓包（58 条请求，完整请求/响应）

## 一、根因

实体券（`quan_kind = 2`）的算价**不是单步**，抓包确认的标准链路是：

| 步骤 | 接口 | 入参 | 结果 |
|---|---|---|---|
| ① 验券 | `POST order/voucher/price/` | `voucher_code` + `order_id` | `{"surcharge_price":0,"pay_price":0,"surcharge_msg":""}` |
| ② 算价 | `POST order/change/` | `discount_type=TP_VOUCHER`、`voucher_code_type=VGC_T`、`card_id=""`、`pay_type=WECHAT`、`voucher_code` | `voucher_use.use_num=1`、`ticket_payment_total_price=0` |
| ③ 支付 | `POST order/payment/` | `order_id` + `mobile` + `pay_type=WECHAT` | `total_price=0` 成功 |

我们只做了 ②（上一轮已把 `TP_VOUCHER`/`VGC_T`/空卡/`WECHAT` 对齐），**缺 ① 验券**，
所以算价报 4004「获取兑换券验券异常」。

抓包同时印证了另一条约束：**实体券不能用会员卡支付**。人工第 2 次算价带
`card_id=370977` + `pay_type=MEMBER`，返回另一个 4004：

```
{"ret":0,"sub":4004,"msg":"请切换其他支付方式使用该券","data":{}}
```

去掉卡、改 `WECHAT` 后立刻成功。

## 三、核心变更

### 1. 验券（新增）

```js
// orderManage.js
async verifyVoucher({ voucher_code, lockOrderId, cinema_id, session_id }) {
  const params = { voucher_code, order_id: lockOrderId, cinema_id, session_id };
  this.logger.infoSave("实体券验券参数", params);
  const res = await this.appApi.getVoucherPrice(params); // 失败不吞，交由调用方转单
  this.logger.infoSave("实体券验券返回", res);
  return res?.data;
}
```

`cinema_id` / `session_id` 仅用于请求拦截器改写 URL 与 `token` 头（会被从 body 剥离），
`order_id` 即本次锁座单号。抓包 body 只有 `voucher_code` + `order_id`，改造后实际发出的
body 与之一致。

### 2. 多张券（多张票）验券

接口只接受**单个** `voucher_code`，故按选中券码逐张串行验券：

```js
// orderManage.js
async verifyVouchers({ voucher_codes = [], lockOrderId, cinema_id, session_id }) {
  const surchargeList = [];
  for (const voucher_code of voucher_codes) {
    surchargeList.push(await this.verifyVoucher({ voucher_code, ... }));
  }
  return surchargeList;
}
```

- `buyTicket.js` 传入 `useQuan.map(item => item.couponCode)`（`useQuan` 已按 `ticket_num` 截取，
  且券码在 `mergeQuanList` 中已去重，不会重复验同一张）；
- 任一张失败立即抛出 → 外层 `errorSave` + 转单，不会继续验后面的券；
- 每张券都用**同一个** `lockOrderId`；
- 之后算价的 `voucher_code` 仍是逗号拼接的全部券码（与抓包一致）。

### 3. 算价与支付

```js
// priceCalculation：券种2 时（上一轮已实现）
params.discount_type = "TP_VOUCHER";
params.voucher_code_type = "VGC_T";
params.card_id = "";
params.pay_type = "WECHAT";

// createOrder 调用（本轮）
pay_type: offerRule?.quan_kind == 2 && useQuan?.length ? "WECHAT" : "MEMBER"
```

`pay_type` 的判定**必须同时满足「券种2」和「本次确实用了券」**：否则用卡订单
（`offer_type=2`）若 `offerRule` 恰好带出 `quan_kind=2`，会被误改成 `WECHAT`。
`createOrder` 不传 `pay_type` 时仍为 `MEMBER`（电子券不变）。

### 4. 卡使用量 / 卡余额（复查补充）

原逻辑在「用券且 `quan_fee > 0`」时会挑一张卡，支付成功后据此
`updateCardDayUse` 记卡使用量并 `syncCardAfterPayment` **按 `paymentAmount` 扣减本地卡余额**
（`cardBalanceSync.js:118` `balance = cardBalance - paymentAmount`）。

实体券已确定不走会员卡（算价空卡 + 支付 `WECHAT`），故此处也必须排除，否则会
**凭空扣减本地卡余额并虚增卡使用量**，进而污染后续报价：

```js
if (
  offerRule.offer_type === "1" &&
  offerRule.quan_fee > 0 &&
  offerRule.quan_kind != 2   // 实体券不用卡
) { card_id = ...; }
```

代价：实体券若配置了 `quan_fee > 0`，手续费将走 WECHAT 而非会员卡（抓包场景 `quan_fee = 0`）。
盈利仍由既有「支付金额 > 券手续费×票数 → 转单」把关。

## 五、回归风险评估

| 风险 | 评估 | 缓解 |
|---|---|---|
| **多张票的验券调用方式** | 中：HAR 仅 1 张票，接口签名只接受单个 `voucher_code`，按**逐张**实现。若服务端实际要求一次性传入全部券码，多张票仍会 4004 | 上线后先用 2 张票的实体券订单验证：「实体券验券参数」应出现 2 条且算价成功；若失败，改为拼逗号一次调用（改动点集中在 `verifyVouchers` 一处） |
| 验券补差价（`pay_price > 0`） | 低-中：本次只记录不拦截；补差价会体现在算价的 `ticket_payment_total_price`，仍由既有「支付金额 > 券手续费×票数 → 转单」把关 | 观察「实体券验券返回」日志中的 `pay_price` |
| 实体券 `quan_fee > 0` 时手续费改走 WECHAT | 低：与「实体券不能用会员卡」一致；盈利校验不变 | 若业务要求手续费仍从卡扣，需回到「带卡 + MEMBER」并验证是否与平台限制冲突 |
| 支付改 `WECHAT` 对电子券的影响 | 无：`pay_type` 仅在「券种2 且用券」时为 `WECHAT`，其余 `MEMBER` | 67 例回归通过 |
| `ticket_pack_goods` 差异 | 极低：抓包为单个空格 `" "`，我们传 `""`；失败订单的 4004 与该项无关 | 出现相关报错再对齐 |
| 验券与算价之间状态 | 低：`order_id` 绑定本次锁座单，转单时随座位释放失效；抓包中人工重算前会再次验券 | 单次出票验一次即算价；重试沿用重新锁座流程 |

## 六、上线观察指标

1. 实体券订单日志应出现完整序列：
   `实体券验券参数`（N 条，N = 票数）→ `实体券验券返回`（N 条）→ `计算价格参数`
   （`TP_VOUCHER`/`VGC_T`/空卡/`WECHAT`）→ `计算价格返回`（`voucher_use.use_num` = 票数、
   `ticket_payment_total_price` = 0）→ `创建订单参数`（`pay_type: WECHAT`）；
   并且**不应**出现「支付卡信息」/「出票后同步单张卡余额」（实体券不用卡）；
2. 电子券订单：无「实体券验券」日志，`pay_type` 仍 `MEMBER`，成功率持平；
3. 关注 `实体券验券异常，走转单` 的 `sub/msg`：
   - `获取兑换券验券异常` → 券状态/影院侧问题，需人工核对；
   - `请切换其他支付方式使用该券` → 仍带了卡，排查 `quan_kind` 是否透传正确。
