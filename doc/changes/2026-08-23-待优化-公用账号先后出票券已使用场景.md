# 待优化：公用账号先后出票「券已使用」场景（其他系列）

日期：2026-08-23

## 背景

lma（卢米埃）系列已实现「券已使用 → 换券重新锁座」逻辑（见 `2026-08-23-lma券已使用换券重新锁座.md`）。
其他影院系列存在同类"公用账号先后出票，后一单选到前一单刚消耗的券"场景，暂不修改，先记录待优化。

## 场景说明

同一影院账号被多个订单共用，先后/并发出票时：
1. 前一单从账号拉取券列表并锁座/出票消耗若干券
2. 后一单拉券时，前一单消耗的券尚未写入 ticket_record（queryUsedQuanList 查的是出票记录，存在落库竞态窗口）
3. 后一单选到已用券 → 锁座/创建订单报"券已使用"类错误 → 转单或手动处理

## 各系列现状与改造方向（暂不实施）

| 系列 | 锁座/建单带券方式 | 现状 | 改造方向 |
|---|---|---|---|
| ume / h5ume | 先锁座后建单，建单带券 | h5ume 已有换券重试（`retryCreateOrderWithCouponSwap`），ume 待确认 | 沿用 h5ume 的备选券池+换券重试模式 |
| sfc | 建单带券 | 无换券重试 | 参考 lma 方案：备选池/重拉 + 重新建单 |
| wanda | 建单带券（券+卡组合） | 无换券重试 | 需评估券+卡组合下换券的支付结构重建 |
| chenxing / jinyi / fenghuang | 建单带券 | 无换券重试 | 参考 lma 方案 |

## 注意事项

- 各系列"锁座失败"语义不同：lma 锁座失败=订单未创建；其他系列可能是先锁座后建单，
  换券重试前需确认是否需要先取消已锁订单再重试
- 换券策略（备选池优先/重拉）、失败券是否写库、耗尽兜底（换号/转单）需按系列单独评估
