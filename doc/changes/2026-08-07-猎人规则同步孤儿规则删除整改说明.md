# 猎人规则同步孤儿规则删除整改说明

> 日期：2026-08-07
> 状态：**已实施并测试通过**
> 说明：本文件记录猎人规则双向同步检查（`checkAndUpdateLierenRuleState`）中"平台有、本地无"孤儿规则由**仅禁用**改为**已禁用即删除**的整改目标、方案、实现与验收。
>
> 目标：修复规则同步修复后"每次检查/修复仍重复报告同样几条不一致、永远无法收敛"的问题——已禁用的平台孤儿规则应在修复时**直接删除**，使双向检查收敛为 0 条不一致。

---

## 一、背景与问题

`src/mixins/useLierenOfferRuleSyncFun.js` 的 `checkAndUpdateLierenRuleState` 在**每次登录**（`login/index.vue`）与**手动点击"规则同步修复"**（`offerRule/index.vue`）时执行猎人平台规则双向同步检查。对"猎人平台有、本地无"的孤儿规则（`platOnly`），原实现只调用 `ruleState` **禁用**，从不删除。

**问题表现**（控制台日志）：

```
⚠ 猎人平台有但本地未同步的规则（platOnly）: 2 条，将自动禁用
  已禁用猎人孤儿规则: rule_id=2163468 name="_10293821"
  已禁用猎人孤儿规则: rule_id=2467568 name="华通汕头"
猎人规则同步统计: 本地已同步 60 条, 猎人平台固定价 62 条, 双向匹配 60 条, ⚠猎人孤儿 2 条
```

**根因**：孤儿判定**不区分状态**——只要平台存在该规则、本地无匹配，就计为不一致。仅禁用（state→0）后规则仍存在于平台，下次检查依旧命中孤儿判定，于是：

> 修复 → 禁用 2 条 → 再检查仍是 2 条不一致 → 再修复再禁用 → **永不收敛**

且每次登录都会重复执行该动作并重复报警，形成持续的噪音与"检查永远过不了"的假象。

---

## 二、整改方案（已与用户确认）

| 平台孤儿规则状态 | 原行为 | 新行为 |
|---|---|---|
| 已禁用（`state === 0`） | 仅再禁用一次（无实际效果） | **直接删除**（`ruleDel`），检查收敛 |
| 启用中（`state === 1`） | 禁用 | 仍先**禁用**（防止误删人工在平台手动创建的规则），下次修复时因已禁用而被删除 |
| 状态未知（`null`/`undefined`/异常值） | 禁用 | **按禁用处理**（catch-all，非 0 即禁用，可逆、防误删），下次修复时删除 |

设计要点：

1. **删除只针对已禁用的规则**：纯清理，无行为影响；启用中的规则只禁用（可逆），避免一次性销毁可能人工创建的平台规则。
2. **状态未知兜底**：筛选采用 `state !== 0` 归入禁用分支（非严格 `=== 1`），保证任何异常状态都不会被静默跳过——否则会重新引入"永不收敛"问题。
3. **删除失败不中断**：单条 `ruleDel` 失败仅 `console.error` 后继续处理其余规则，失败项下轮检查自动重试。
4. **多机并发安全（已确认）**：同角色（`rule`）下不同用户的 AK/SK 账号与机器规则**公用**，所有机器看到的本地规则集与平台规则集一致，孤儿集合一致，删除动作在各机器间行为一致、无互相误删风险。

## 三、代码改动

### 3.1 `src/mixins/useLierenOfferRuleSyncFun.js`（`checkAndUpdateLierenRuleState`）

- 新增 `deleteCount` 计数（仅删除成功时累加）。
- 孤儿规则处理拆分为两阶段：
  - `platOnlyDelete = platOnlyRules.filter(r => r.state === 0)` → 逐条 `lierenApi.ruleDel` 删除；
  - `platOnlyDisable = platOnlyRules.filter(r => r.state !== 0)` → 逐条 `lierenApi.ruleState(state: 0)` 禁用（保留原安全行为）。
- 每条操作后保留 200ms 间隔，避免触发猎人平台 429 限流。
- 操作日志（`batchAddRuleOperationLog`）按动作区分：
  - 删除：`operation_type = "sync_delete"`，`new_status = null`，原因"…平台已禁用），自动删除"；
  - 禁用：`operation_type = "sync_bidirectional"`，`old_status` 按既有"非 1 即 2"约定映射，原因"…自动禁用"。
- 控制台日志同步更新：孤儿警告提示"已禁用 N 条将自动删除、其余 M 条先自动禁用（下次修复时删除）"；汇总新增"删除孤儿 X 条"。
- 失败处理加固：catch 中改用 `formatErrInfo(err)` 打印错误（原 `err.message` 在非对象 rejection 下会抛 TypeError 中断整个检查）。

### 3.2 `src/common/tests/lieren-sync-logging.test.js`

新增/调整 7 个用例，覆盖：

| 用例 | 验证点 |
|---|---|
| 启用中孤儿（state=1）先禁用 | `ruleState` 调用、`ruleDel` 不被调用、日志 `sync_bidirectional` |
| 已禁用孤儿（state=0）自动删除 | `ruleDel` 调用、`ruleState` 不被调用、日志 `sync_delete`（new_status=null） |
| 启用 + 已禁用混合 | 分别走禁用/删除分支，批量日志顺序（删除在前、禁用在后） |
| 状态未知（state=null）孤儿 | 按禁用处理而非静默跳过，`old_status` 按"非 1 即 2"记 "2" |
| 删除失败 | 失败不中断循环、其余规则继续处理 |

> 测试数据注意：本地规则 `platRuleId` 为 "999"，孤儿用例的平台规则 id（"888"/"777"）不得与其冲突，否则会被误判为已匹配规则而非孤儿。

## 四、验收标准

1. 存在"平台已禁用、本地无"的孤儿规则时，执行一次"规则同步修复"后，该规则被**删除**（平台规则列表不再存在）。
2. 修复后再次执行检查/修复，`⚠猎人孤儿` 数量收敛为 0，不再重复报告同样几条不一致。
3. 启用中的孤儿规则第一次修复被禁用并提示"下次修复将删除"，第二次修复被删除。
4. 操作日志中删除动作记 `sync_delete`、禁用动作记 `sync_bidirectional`，可追溯。
5. 单条删除失败不影响其他规则处理，控制台有 `删除猎人孤儿规则失败` 错误日志。
6. 匹配规则的完整同步修复（状态/座位数）、本地孤儿（localOnly）反向检查、统计输出不受影响。
7. 单元测试 16/16 通过（`npx jest src/common/tests/lieren-sync-logging.test.js`）。

## 五、审查与验证结论

- 独立代码审查：核心逻辑正确，参数与 `lierenApi.ruleDel` 定义一致，无回归；发现 1 个 Important 问题（state 严格二分导致异常状态被静默跳过，属行为回归）已修复，2 个 Minor 加固（错误打印、测试缺口）已处理。
- 测试验证：`lieren-sync-logging.test.js` **16/16 通过**；全量测试中 5 个失败套件为既有环境问题（jest 缺失 `@/utils/auth` 模块映射，与本次改动无关，stash 基线验证一致）。
- 多机共用账号风险：经与用户确认，同角色账号与机器规则公用，不存在 A 机误删 B 机规则场景。

## 六、遗留说明

- 批量日志 `success` 字段仍硬编码为 1（与原禁用路径同模式），单条失败仅控制台报错、日志不记 `success: 0`——失败项下轮检查自动重试，可接受；如需完整失败留痕可后续按 `lierenOfferRuleDelPlat` 的失败日志模式增强。
- `useCheckLierenRuleSync.js`（只读检查）不做删除，保持不变。
