# 报价出票日志追踪整改细化设计方案

> 日期：2026-08-06
> 状态：**待评审**
> 关联：本方案是《2026-08-06-报价出票日志追踪与根因缓存整改说明.md》（目标态规范）的**实施细化方案**，针对该规范在首次全系列推广中出现"各系列完成度参差不齐"的问题，重新拆解为"框架先行 → P0 止血 → 单系列示范 → 评审 → 渐进式推广"的落地路径。
>
> 设计目标：让**单个订单**的报价、出票流程在日志中形成一条可读、可检索、可定位的环节时间线；失败根因不被降级动作覆盖；各系列按统一清单逐项验收，消除完成度误差。

## 一、现状诊断摘要（回退到 5ebdfa3 后的实际状态）

## 二、总体策略：三阶段渐进式

```
阶段一：Logger 框架改造（基础先行，一次性完成）
  └─ 根因缓存 + 降级前缀 + 成功终态正则 + 自动前缀拼接 + 大对象裁剪函数
         ↓
阶段二：P0 止血修复（集中修复运行期 bug，保证功能正常）
  └─ 10 处 P0 bug + 核心框架 console 清理
         ↓
阶段三：日志规范化（chenxing 示范 → 评审 → 渐进式推广）
  └─ chenxing 完整改造 → 用户评审确认标准 → 逐系列推广（每系列独立验收）
```

**关键原则**：
1. 阶段一、二不依赖系列改造，可独立完成并验证
2. 阶段三以 chenxing 为示范，**评审通过后**才推广，避免错误标准扩散
3. 每个系列独立提交、独立验收，不批量推进

## 三、阶段一：Logger 框架改造设计

### 3.1 改造范围（仅 `src/common/logger.js` + 新建裁剪函数）

#### 3.1.1 新增常量

```javascript
// 降级/补救型日志前缀：转单/换号/释放座位/取消订单/申请换座 的 errorSave 表示"怎么补救"，
// 不作为失败根因（根因取最近一次非降级 errorSave）
const REMEDY_PREFIXES = [
  "[出票]转单",
  "[出票]换号",
  "[出票]释放座位",
  "[出票]取消订单",
  "[出票]申请换座"
];
// 主链路环节成功终态后缀（如"锁定座位-成功"）：出现后作废之前缓存的根因
// 注意用 [^-]* 而非 [^-]+：成功紧贴 "-"（如"锁定座位-成功"）时 + 会吞掉"成"导致永不匹配
const SUCCESS_SUFFIX_RE = /-[^-]*成功$/;
```

#### 3.1.2 constructor 新增字段

```javascript
// 根因缓存：最近一次非降级 errorSave，环节成功终态时重置
this._rootErrCache = null;
// _lastErrCache 已有，保留（每次 errorSave 覆盖，作"最近错误"兜底）
```

#### 3.1.3 `log()` 改造：自动拼接流程前缀

```javascript
log(level, message, isSave, meta) {
  const timestamp = new Date().toLocaleString().replaceAll("/", "-");
  // 自动拼接流程前缀（已带 [报价]/[出票] 前缀的日志不重复拼）
  const des = this._applyFlowPrefix(message);
  // ... 其余不变，用 des 替代原 message
}

// 依据日志类型自动拼接流程前缀：type=1 报价拼 [报价]，type=3 出票拼 [出票]，其余不拼
_applyFlowPrefix(message) {
  if (typeof message !== "string" || !message) return message;
  if (message.startsWith("[报价]") || message.startsWith("[出票]")) {
    return message;
  }
  const prefix = this.getFlowPrefix();
  return prefix ? `${prefix}${message}` : message;
}

getFlowPrefix() {
  if (this.type === 1) return "[报价]";
  if (this.type === 3) return "[出票]";
  return "";
}
```

> **影响面**：所有调用方**无需手写** `[报价]/[出票]` 前缀，由 logger 依据实例 type 自动拼接。双流程共用方法（cinemaManage/seatManage/cardQuanManage）打同一句日志，会因 logger 实例不同而自动显示正确前缀。

#### 3.1.4 `errorSave()` 改造：根因缓存

```javascript
errorSave(message, meta) {
  const des = this.log(Logger.levels.ERROR, message, true, meta);
  this._lastErrCache = { message: des, meta };
  // 补救型 errorSave 不覆盖根因；其余 errorSave 作为根因
  if (!REMEDY_PREFIXES.some(prefix => des?.startsWith(prefix))) {
    this._rootErrCache = { message: des, meta };
  }
}
```

#### 3.1.5 `infoSave()` 改造：成功终态重置根因

```javascript
infoSave(message, meta) {
  const des = this.log(Logger.levels.INFO, message, true, meta);
  // 主链路环节成功终态作废旧错误；降级链路成功与"超时当成功"不重置
  if (
    !des?.includes("超时当成功") &&
    SUCCESS_SUFFIX_RE.test(des || "") &&
    !REMEDY_PREFIXES.some(prefix => des?.startsWith(prefix))
  ) {
    this._rootErrCache = null;
  }
}
```

#### 3.1.6 `getLastErrMsg`/`getLastErrMsgAndInfo` 改造：优先根因

```javascript
getLastErrMsg() {
  if (this._rootErrCache) return this._rootErrCache.message;
  if (this._lastErrCache) return this._lastErrCache.message;
  const errInfoObj = this.logList.filter(item => item.level === "error").reverse()?.[0];
  return errInfoObj?.des || "";
}

getLastErrMsgAndInfo() {
  try {
    const cache = this._rootErrCache || this._lastErrCache;
    if (cache) {
      const { message, meta } = cache;
      return {
        err_msg: message,
        err_info: formatErrInfo(meta?.error || meta) || ""
      };
    }
    // ... 回退 logList 逻辑不变
  } catch (error) {
    return { err_msg: "", err_info: "" };
  }
}
```

#### 3.1.7 新建大对象裁剪函数（放 `src/common/autoTicket/common/logTrim.js`）

## 六、验收标准（总）
