# 系列日志打点整改推广（chenxing 模式 → 其它 7 系列）

> 日期：2026-08-20
> 前置：《2026-08-18-报价出票日志整改-最终详细设计文档.md》V4.8（本文唯一权威依据，冲突以 V4.8 为准）
> 范围：**仅"① 失败现场降级/辅助前缀 + errorSave 语义修正"**（用户裁定）。calc_path/use_path/字段采集/轮询收敛不在本次范围。

## 一、背景与目标

- V3 日志通道（v3Mode 判定/L1 收窄/L2 上传）是 logger.js **公共逻辑**，已全系列生效（字典按 `app_type_code` 白名单）；
- 但各系列**打点层未改造**（grep 证实 7 系列零 `降级-`/`辅助-` 前缀、零 calc_path/use_path）——chenxing 之外系列的 errorSave 语义混乱：
  1. **补救动作**（换号/转单/申请换座/释放座位/取消订单等）用无前缀 errorSave → 被根因缓存当作"真实失败" → 失败原因被补救动作污染（getLastErrMsg/err_msg 错）；
  2. **辅助操作**（同步卡余额/更新券库存/查券等）无前缀 → 同上污染；
  3. **正常路径误用 error**（如"平台已报价"/"规则由平台报价"等正常分流当 error 打）→ v3Mode 下触发 L1 入库（errorSave 不在收窄范围）+ 污染根因。
- **目标**：7 系列打点语义对齐 chenxing，L1 异常日志准确、根因缓存真实有效。

## 二、改造规则（判定基准）

| 类型 | 前缀 | 级别 | 效果 |
|------|------|------|------|
| 补救动作（换号/转单/申请换座/释放座位/取消订单等） | `降级-` | 进入/异常用 `errorSave`；成功用 `infoSave`/`warnSave` | 不设根因（REMEDY_KEYWORDS 排除）；成功补救 v3Mode 下白名单保留入库（补救结果可见） |
| 辅助操作（同步卡余额/更新券库存/查券等） | `辅助-` | 异常用 `errorSave`；成功用 `infoSave`/`warnSave` | 同上 |
| 真实失败（出票/锁座/报价失败等业务失败） | 无前缀 | `errorSave` | 设根因 = 失败真相 |
| 正常路径误用 error（正常分流/决策/终态） | 无前缀 | 改 `warnSave` | v3Mode 下不入 L1、不污染根因；非 v3Mode 行为仅级别变化 |

- 前缀只做**语义标记**（L1 收窄白名单 + 根因排除判定），不改变日志内容；
- 级别保持真实：失败=error、成功=info/warn（成功的补救动作**不加** error 级别，避免"假异常"）。
- ⚠️ 级别与前缀的优先级：**成功补救动作**（如"释放座位-成功"）若原来是 `errorSave`，改为 `infoSave("降级-释放座位-成功")`；若原来是 `infoSave` 但无前缀，加前缀即可。
