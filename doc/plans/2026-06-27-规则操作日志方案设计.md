# 规则状态变更 & 猎人同步日志方案设计

## 概述

为解决"SV 数据库规则状态被异常禁用"和"猎人平台同步过程"缺乏可追溯日志的问题，设计一套完整的操作日志系统：后端新建日志表 + API，前端在关键节点埋点写入。

---

## 一、数据库设计

### 1.1 新建表 `rule_operation_log`

```sql
CREATE TABLE IF NOT EXISTS rule_operation_log (
    id INT AUTO_INCREMENT PRIMARY KEY,
    rule_id INT COMMENT '关联的规则ID',
    rule_name VARCHAR(255) COMMENT '规则名称（冗余，便于查询）',
    shadow_line_name VARCHAR(100) COMMENT '影线名称',
    operation_type VARCHAR(50) NOT NULL COMMENT '操作类型',
    old_status VARCHAR(10) COMMENT '变更前状态',
    new_status VARCHAR(10) COMMENT '变更后状态',
    old_seat_num VARCHAR(10) COMMENT '变更前座位数',
    new_seat_num VARCHAR(10) COMMENT '变更后座位数',
    plat_name VARCHAR(50) DEFAULT 'lieren' COMMENT '目标平台',
    trigger_source VARCHAR(100) COMMENT '触发来源',
    change_reason VARCHAR(500) COMMENT '变更原因说明',
    success TINYINT DEFAULT 1 COMMENT '操作是否成功 1-成功 0-失败',
    error_msg TEXT COMMENT '失败时的错误信息',
    operator VARCHAR(100) COMMENT '操作人',
    ext_data TEXT COMMENT '扩展数据(JSON)',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_rule_id (rule_id),
    INDEX idx_operation_type (operation_type),
    INDEX idx_trigger_source (trigger_source),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
COMMENT='规则操作日志表：记录规则状态变更及猎人平台同步操作';
```

### 1.2 字段枚举定义

**operation_type（操作类型）**：

| 值                   | 含义                           | 使用场景                        |
| -------------------- | ------------------------------ | ------------------------------- |
| `status_change`      | 规则状态变更（仅状态字段变化） | 手动切换开关 / 券库存触发       |
| `rule_create`        | 规则新增                       | 用户新增保存规则                |
| `rule_update`        | 规则编辑                       | 用户编辑保存规则                |
| `sync_add_update`    | 同步规则到平台（新增/修改）    | `lierenOfferRuleSyncPlat`       |
| `sync_status`        | 同步状态到平台                 | `lierenOfferRuleEditStatusPlat` |
| `sync_delete`        | 从平台删除规则                 | `lierenOfferRuleDelPlat`        |
| `sync_bidirectional` | 双向同步检查修复               | `checkAndUpdateLierenRuleState` |

**trigger_source（触发来源）**：

| 值                  | 含义                      |
| ------------------- | ------------------------- |
| `manual_toggle`     | 用户手动切换启用/禁用开关 |
| `form_save`         | 用户通过表单保存规则      |
| `quan_stock_zero`   | 券库存归零自动禁用        |
| `quan_stock_update` | 券库存变化更新座位数      |
| `login_sync`        | 登录时双向同步检查        |
| `manual_fix`        | 用户点击"规则同步修复"    |
| `rule_edit_save`    | 编辑规则保存时同步        |
| `rule_add_save`     | 新增规则保存时同步        |
| `rule_delete`       | 删除规则时同步删除        |
| `no_offer_today`    | "当日不报"操作            |

## 二、后端实现

### 2.1 新建 `auto-ticket-service/api/ruleOperationLog.js`

参照 `api/ruleRecord.js` 模式，提供：

- `createTable()` — 建表
- `addLog(params)` — 写入单条日志
- `batchAddLogs(logs)` — 批量写入日志
- `queryLogs(params)` — 分页查询日志，支持按 rule_id / operation_type / trigger_source / 时间范围 筛选

### 2.2 新建 `auto-ticket-service/routes/rule_operation_log.js`

参照 `routes/rule_record.js` 模式：

- `router.prefix("/ruleOperationLog")`
- `GET /create` — 建表
- `POST /add` — 新增日志（需 auth）
- `POST /batchAdd` — 批量新增日志（需 auth）
- `GET /query` — 查询日志列表

### 2.3 修改 `auto-ticket-service/app.js`

在业务路由注册区域新增一行：

```javascript
const rule_operation_log = require("./routes/rule_operation_log");
// ...
app.use(rule_operation_log.routes(), rule_operation_log.allowedMethods());
```

## 三、前端实现

### 3.1 修改 `src/api/sv-api.js`

新增两个 API 方法：

```javascript
// 新增规则操作日志
const addRuleOperationLog = params =>
  axios.post("/svpi/ruleOperationLog/add", params);
// 批量新增规则操作日志
const batchAddRuleOperationLog = params =>
  axios.post("/svpi/ruleOperationLog/batchAdd", params);
```

并在 `svApi` 导出对象中添加这两个方法。

### 3.2 埋点位置 #1：状态变更日志

#### A. 用户手动切换 — `src/views/offerRule/index.vue` 的 `editStatus`（约第 740 行）

在 `svApi.updateRuleRecord` 成功后、`ElMessage.success` 之前插入：

```javascript

    rule_id: row.id,
    rule_name: row.ruleName,
```

#### C. 券库存触发 — `src/common/autoTicket/commonQuanStock.js` 的 `checkLierenFixedRuleByQuanStock`（约第 250-285 行）

在 `svApi.updateRuleRecord(jiqiuRule)` 成功后插入：

### 3.3 埋点位置 #2：猎人同步日志

所有同步函数在 `src/mixins/useLierenOfferRuleSyncFun.js` 中。

#### D. 同步规则到平台（新增/修改）— `lierenOfferRuleSyncPlat`

**成功后**（`lierenApi.ruleAdd` 返回后）：

```javascript
svApi
  .addRuleOperationLog({

    rule_name: ruleInfo.ruleName,
    shadow_line_name: ruleInfo.shadowLineName,
    operation_type: "sync_add_update",
```

#### G. 双向同步检查 — `checkAndUpdateLierenRuleState`

**平台孤儿规则被自动禁用时**（`platOnlyRules` 循环中）：

```javascript

      rule_id: null,

      shadow_line_name: r.cinema_group || r.cinema_code || "",

```

**状态不一致被修复时**（`stateMismatch` 分支）：

```javascript
svApi
  .addRuleOperationLog({
    rule_id: localRule.id,
    rule_name: localRule.ruleName,
    shadow_line_name: localRule.shadowLineName,
    operation_type: "sync_bidirectional",
    old_status: platRule.state === 1 ? "1" : "2",
    new_status: expectedState === 1 ? "1" : "2",
    plat_name: "lieren",
    trigger_source: "login_sync",
    change_reason: stateMismatch
      ? expectedState === 0
        ? isNoOfferActive
          ? "当日不报生效中"
          : `本地status=${localRule.status}`
        : "本地已启用，同步启用"
      : `座位数不一致(${platRule.seats}→${expectedSeats})`,
    success: syncRes ? 1 : 0,
    ext_data: JSON.stringify({
      platRuleId: platRule.rule_id,
      expectedState,
      expectedSeats,
      localStatus: localRule.status,
      allowOfferTime: localRule.allow_offer_time
    })
  })
  .catch(() => {});
```

## 五、注意事项

1. **日志写入不能阻塞主流程**：所有 `svApi.addRuleOperationLog` 调用使用 `.catch(() => {})` 兜底，日志写入失败不影响业务操作
2. **批量场景用 `batchAdd`**：`checkAndUpdateLierenRuleState` 中 `platOnlyRules` 可能有多条，用 `batchAddRuleOperationLog` 减少请求次数
3. **敏感信息脱敏**：`ext_data` 中的 `params` 快照需注意不要包含 AK/SK 等敏感凭证（或后端做脱敏处理）
4. **operator 字段取值**：前端取 `platTokens().userInfo.rule`（当前登录账号标识）
5. **日志保留策略**：暂不自动清理，后续可视数据量增加定时清理（如保留 90 天）
6. **日志查询**：后续可在规则管理页面增加"操作日志"Tab 或弹窗，调用 `queryLogs` API 按规则 ID 查询历史操作记录
