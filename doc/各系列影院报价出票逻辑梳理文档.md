## 1. 整体架构概览

### 1.1 两层扩展架构

```
┌─────────────────────────────────────────────────────┐
│              票务平台层（Platform）—— 拉单 + 报价      │
│  猎人 / 省APP / 芒果 / 蚂蚁 / 洋葱 / 影划算 ...        │
│  负责：从平台拉待报价订单 → 匹配报价规则 → 提交报价      │
│  代码位置：src/common/platform/queues/               │
└──────────────────────┬──────────────────────────────┘
                       │ 订单中的 app_name 决定走哪个影院系列
                       ▼
┌─────────────────────────────────────────────────────┐
│              影院系列层（Cinema）—— 报价 + 出票        │
│  SFC / UME / H5UME / LMA / 辰星 / 凤凰 / 金逸         │
│  负责：登录影院系统 → 计算报价 → 选座锁座 → 获取取票码   │
│  代码位置：src/common/autoTicket/buyTicket/           │
└─────────────────────────────────────────────────────┘
```

### 1.2 策略工厂模式（STRATEGY_MAP）

文件：`src/common/autoTicket/buyTicket/index.js`

```javascript
const STRATEGY_MAP = {
  chenxing_applet: ChenxingBuyTicket,
  fenghuang_applet: FenghuangBuyTicket,
  jinyi_applet: JINYIBuyTicket,
  lma_applet: LmaBuyTicket,
  sfc_applet: SfcBuyTicket,
  ume_applet: UmeBuyTicket,
  ume_h5: UmeH5BuyTicket
};
```

- `StrategyFactory.createSeatStrategy(order, logger, isTestOrder)` 根据订单的 `app_name` 查找 `GET_APP_INFO(app_name)?.app_type_code`，然后从 STRATEGY_MAP 中取对应类实例化。
- 入口调用链：`commonOfferHandle.js`（报价入口） → 各系列 `offerManage`；出票入口直接通过 `index.js` 路由。

## 2. 核心基类与模板方法流程

### 2.1 BaseBuyTicket（出票基类）

文件：`src/common/core/BaseBuyTicket.js`

#### 构造函数

```javascript
constructor(order, logger, isTestOrder);
```

- 设置 `appFlag`（`order.app_name`）、`order`、`isTestOrder`、`logger`
- 初始化 `currentParamsList`、`currentParamsInx`、`currentSessionId`、`currentPhone`、`offerRule`
- 调用 `this.initModules()`（子类必须实现）

#### 子类必须实现的方法

| 方法                      | 说明                                                                     |
| ------------------------- | ------------------------------------------------------------------------ |
| `initModules()`           | 初始化 platManage、cinemaManage、seatManage、orderManage、cardQuanManage |
| `getCinemaLoginInfo()`    | 获取影院登录信息并设置 currentParamsList/currentSessionId/currentPhone   |
| `oneClickBuyTicket(item)` | 一键买票核心流程，参数 item 包含 otherParams.offerRule                   |

#### 模板方法：singleTicket()

```
① getCinemaLoginInfo()
    └─ 获取该影院登录信息列表，设置 currentParamsList / currentSessionId / currentPhone

② getOrderOfferRule()
    └─ 通过 svApi.queryOfferInfo 从后端查报价记录，设置 this.offerRule
    └─ 测试模式下若无规则，注入调试用默认规则

③ checkOfferRuleRes()
    └─ 校验：offerRule 是否存在、rule_status !== "3"、quan_value !== "jinbaojia"
    └─ 不通过则发送微信通知，返回 { offerRule }

④ platManage.unlockSeatByPlat()
    └─ 根据 plat_name 调用对应平台解锁座位接口
    └─ 失败则走 orderManage.transferOrder() 转单

⑤ oneClickBuyTicket(item)  ← 子类实现的核心
    └─ 传入 { ...this.order, otherParams: { offerRule: this.offerRule } }

⑥ 返回结果：{ profit, qrcode, submitRes, quan_code, card_id, cardNum, offerRule }
    或失败：undefined 或 { offerRule, transferParams }
```

#### 基类提供的工具方法

| 方法                       | 说明                                                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| `getLoginInfoList()`       | 从 `getCinemaLoginInfoList()` 获取登录信息，`shouldSplitLoginByUser()` 控制是否按用户隔离 |
| `shouldSplitLoginByUser()` | 补全报价订单（`need_unsplit_login`）不隔离                                                |
| `validateCouponPrice()`    | 用券价格校验：支付金额 vs 券手续费 × 票数                                                 |
| `coreOneClickBuyTicket()`  | 通用骨架模板（可选迁移使用），通过 hooks 模式串联各步骤                                   |

### 2.2 BaseOfferPrice（报价基类）

文件：`src/common/core/BaseOfferPrice.js`

#### 构造函数

```javascript
constructor({ appFlag, plat_name });
```

- 设置 `appFlag`、`plat_name`、`logger`（null，在 initModules 中初始化）
- `quanInfoList`：存放当前报价规则下查询到的券类型信息（供 maxCostPrice 过滤使用）

#### 子类必须实现的方法

| 方法                                 | 说明                                                    |
| ------------------------------------ | ------------------------------------------------------- |
| `initModules(order)`                 | 初始化 logger、cardQuanManage、cinemaManage、seatManage |
| `getEndMatchOfferRule(order)`        | 获取最终匹配的报价规则                                  |
| `getMemberPrice({order, movieData})` | 获取会员价（仅加价规则需要）                            |
| `calculateFinalPrice(params)`        | 计算最终报价                                            |

#### 模板方法：getEndOfferPrice()

```
① initModules(order)
    └─ 初始化 logger、cardQuanManage、cinemaManage、seatManage

② getEndMatchOfferRule(order)  ← 子类实现
    └─ 规则匹配 → 电影格式过滤 → 券库存校验 → 取最低价/最佳规则

③ 同步平台报价检查
    └─ 检查 fixedOfferToPlatList 配置，若规则需由平台报价则跳过

④ getCostPrice(offerRule)  ← 基类默认实现，子类可覆写
    ├─ offerType="1"（券固定报价）：调 cardQuanManage.getQuanInfo() 查券成本
    │   └─ 多券取最小 quan_cost，存入 this.quanInfoList
    └─ offerType="2"（会员价加价）：直接取 offerRule.memberCostPrice

⑤ calculateFinalPrice(params)  ← 子类实现
    └─ 通常链条：动态调价 → 利润加价 → 夜间顶价 → 超限处理 → 成本利润拆分

⑥ 组装返回
    ├─ maxCostPrice 过滤：offerType="1" 且有 maxCostPrice 时，过滤券类型
    └─ 成功：{ endPrice, offerRule, order_number }
       失败：{ err_msg, err_info, endPrice: null, offerRule }
```

#### 基类提供的工具方法

| 方法                                                 | 说明                                                   |
| ---------------------------------------------------- | ------------------------------------------------------ |
| `getOfferBasePrice(offerRule)`                       | 取基础报价金额（`offerAmount` 或 `memberOfferAmount`） |
| `getRealAddMount({real_member_price, addMountRule})` | 根据加价规则计算真实加价金额（使用 calculateMarkup）   |
| `buildSuccessResponse()` / `buildErrorResponse()`    | 构建成功/失败响应结构                                  |

## 4. 各系列详解

### 4.1 SFC 系列（sfc_applet）

#### 基本信息

- **app_type_code**：`sfc_applet`
- **涉及的具体影院（appFlag）**：`hbchyxd`
- **V3 版本区分**：`sfcV3AppList` 中的影院走 V3 API 逻辑

#### 报价流程

**入口**：`sfc/offerManage.js` 的 `getSfcOfferPrice.getEndOfferPrice()`

```
① initModules(order)
   └─ 初始化 logger、cardQuanManage、cinemaManage、seatManage

② getEndMatchOfferRule(order)
   ├─ offerRuleMatch(order) 获取初始匹配规则列表
   ├─ 电影格式过滤：调 cinemaManage.getMovieInfo(order) 获取 media 字段
   │   └─ 按 film_type 过滤（如 2D/3D）
   ├─ getMinAmountOfferRule(matchRuleList, order, movieInfo)
   │   ├─ offerType="1"（固定报价）：filterFixedRulesByDailyTicketCount 过滤 → 按 offerAmount 排序取最小
   │   └─ offerType="2/3"（会员价加价）：getMemberPrice({order, movieData}) 获取会员价
   │       → getRealAddMount 计算加价 → getCostPrice 计算成本价
   │       → 取 memberOfferAmount 最小的规则
   └─ 返回 endRule

③ getCostPrice(offerRule)  ← 基类默认实现
   ├─ offerType="1"：查券成本 cardQuanManage.getQuanInfo(quanValue, appFlag)
   └─ offerType="2"：直接取 memberCostPrice

④ calculateFinalPrice(params)
   ├─ applyDynamicPricing     # 动态调价
   ├─ applyProfitAddition     # 利润加价（GROUP_LIST 中影院跳过）
   ├─ applyNightMaxPrice      # 夜间顶价
   ├─ handleOverrunCheck      # 超限处理
   └─ calculateCostProfit     # 成本利润校验
```

**会员价获取（getMemberPrice）**：

1. 调 `cinemaManage.getMovieInfo(order)` → 获取 movieInfo（场次信息）
2. 调 `seatManage.getSeatLayout({city_id, cinema_id, show_id, session_id})` → 获取座位布局
3. 取分区最高价 `area_price` 作为 `member_price`
4. V3 app：`member_price` 用 `normal_price`
5. `memberPriceRule="2"` 时，使用 `calculateMostSeatPrice` 按座位占比取价格
6. 查卡折扣：`svApi.queryCardList` → 过滤 → 按 `card_discount` 排序取最小折扣
7. 成本价 = `member_price * discount / 100`

### 4.3 H5UME 系列（ume_h5）

H5UME 与 UME（小程序）共享影院后端，但走 H5 接口，数据结构有差异。

#### 基本信息

- **app_type_code**：`ume_h5`

**差异**：

       └─ 锁座参数包含 hallId、scheduleId、scheduleKey 等

- **测试模式**：用券场景下不调创建订单接口（避免实际创建），直接打印参数 + 释放座位

### 4.4 LMA 系列（lma_applet）

#### 基本信息

- **app_type_code**：`lma_applet`
- **涉及的具体影院（appFlag）**：`lma`（卢米埃影城）

#### 报价流程

**入口**：`lma/offerManage.js` 的 `getLmaOfferPrice.getEndOfferPrice()`

```
① initModules(order)

② getEndMatchOfferRule(order)
   ├─ offerRuleMatch → 电影格式过滤（language_type 字段，如 "2D"）
   ├─ getMinAmountOfferRule(matchRuleList, order, movieInfo)
   │   ├─ offerType="1"：filterFixedRulesByDailyTicketCount → 取最小 offerAmount
   │   │   └─ 按 quanValue 过滤（LMA 券库存/黑名单）
   │   └─ offerType="2/3"：getMemberPrice → 计算 real_member_price
   │       ├─ 获取 movieInfo（场次信息，含 member_price、price 字段）
   │       ├─ 若有 show_id：getSeatLayout 取 label_arr 分区最高价
   │       │   └─ member_price = Math.max(movieInfo.member_price, 分区最高价)
   │       ├─ 🔑 LMA 特殊 -5元券：
   │       │   ├─ 条件：localStorage.lmaIsUseQuan == "1" 且 real_member_price >= 33
   │       │   ├─ member_price = (real_member_price - 5) * discount / 100
   │       │   └─ member_price += quan_cost（quan_cost 查 "lma-5" 券信息）
   │       └─ 常规：member_price = real_member_price * discount / 100
   │   └─ 取 memberOfferAmount 最小的规则
   └─ 返回 endRule

③ getCostPrice(offerRule) ← 基类默认实现

④ calculateFinalPrice(params)
   └─ applyDynamicPricing → applyProfitAddition → applyNightMaxPrice → formatFinalPrice
```

**会员价获取（getMemberPrice）核心逻辑**：

1. `cinemaManage.getMovieInfo(order)` → 获取场次（member_price、price 字段）
2. 有 show_id 时调 `getSeatLayout` → 取分区最高价 `bigPrice` → `member_price = Math.max(member_price, bigPrice)`
3. member_price <= 0 时用 `price`（非会员价）
4. member_price === 0 → 不报价返回 null
5. 查卡列表 → 过滤（日/月限额、指定影院 linkCinemaIds） → 按 card_discount 排序取最小折扣
6. 成本价 = member_price \* discount / 100
7. -5 元券：real_member_price - 5 后再算折扣，加上券成本

#### 出票流程

**入口**：`lma/buyTicket.js` 的 `LmaBuyTicket.oneClickBuyTicket()`

```
⑤ oneClickBuyTicket(item) 首次出票：

   [1] 获取影院信息 → cinemaManage.getBuyPrevCinemaInfo({cinema_code, appFlag})
       └─ 获取城市列表 → 匹配城市 → 获取影院列表 → 匹配影院（cinema_id、city_id）

   [2] 获取放映列表 → cinemaManage.getMoviePlayInfo({cinema_id})
       └─ 返回 film 数组

   [3] 匹配影片 → getMovieInfoFromFilmName({filmName, movieData})
       └─ 得到 short_code

   [4] 获取放映日期 → cinemaManage.getMoviePlayDate({cinema_id, short_code})
       └─ LMA 使用 formatTimeStrByLma 格式化日期（YYYYMMDD 格式）

   [5] 匹配场次：
       ├─ 从 playDateList 中找 start_day（支持 isNextDay 跨天 → getPreviousDay）
       ├─ 从 targetDate.session 中按 start_time 匹配
       └─ 同名影厅用 findMostRepeatedChars 相似度排序

       └─ 用券时按可用券数量重排登录顺序

   [7] 获取座位布局 → getSeatLayout({cinema_id, show_id, lmaToken})
       └─ 返回 seatData、label_arr

   [8] 目标座位匹配 → getTargetSeat({lockseat, seatList, label_arr, ticket_num})
       └─ 解析座位名 "X排Y座"

   [9] 🔑 锁座（LMA 锁座即创建订单） → seatManage.lockseatByApp()
       └─ 返回 order_str（订单号）

        └─ 调 GET /lma/mp/iorder/get_order 接口

        ├─ 券单：paymentAmount > quan_fee_total → 转单
        └─ 卡单：检查卡满、利润扣减

   [13] 购买 → orderManage.buyTicket({order_str, lmaToken})

   [14] 获取取票码 → orderManage.payOrder({order_str, booking_id, lmaToken})

   [15] 上传取票码 → orderManage.getQrcodeUploadByPlat(qrcodeInfo)
```

**LMA 与 SFC/UME 的关键差异**：

- **锁座即创建订单**：LMA 的锁座接口返回 `order_str`，这就是订单号，不需要单独的创建订单步骤
- **支付价格来自接口**：调 `get_order` 接口获取实际支付价格，不自己计算
- **-5 元券机制**：localStorage `lmaIsUseQuan` 开关控制，会员价 >= 33 时可减 5 元
- **日期格式**：LMA 使用 `formatTimeStrByLma`（YYYYMMDD 格式）
- **lmaToken**：session_id 映射为 lmaToken 字段传给接口
- **券类型查 "lma-5"**：固定券类型名

### 4.6 凤凰（fenghuang_applet）

#### 基本信息

- **app_type_code**：`fenghuang_applet`
- **涉及的具体影院（appFlag）**：`umexin` 等

#### 报价流程

**入口**：`fenghuang/offerManage.js` 的 `getFenghuangOfferPrice.getEndOfferPrice()`

流程与辰星类似（规则匹配 → 电影格式过滤 → 取最低规则 → 标准 5 步调价链）。

**会员价获取（getMemberPrice）— 按票数获取座位价格**：

1. 从座位布局获取 `areaInfoList`（区域价格）和 `seatData`
2. 按价格从高到低排序区域
3. `memberPriceRule="2"` 时按座位占比排序
4. 调 `getSeatPriceByTicket()` 按票数获取对应座位
5. 调 `getSeatPrice()` 获取这些座位的总价格
6. 总价 / 票数 = 单张票会员价

#### 出票流程

**入口**：`fenghuang/buyTicket.js` 的 `FenghuangBuyTicket.oneClickBuyTicket()`

```
⑤ oneClickBuyTicket(item) — 首次出票：

   [1] 延迟初始化 cardQuanManage、cinemaManage（同辰星）

   [2] 获取购票前影院信息 → cinemaManage.getBuyPrevCinemaInfo({cardQuanManage})
       └─ 内部做登录排序、可用卡列表维护

   [3] 获取目标座位 → seatManage.getTargetSeat(buyTicketInfo)
       └─ 返回 targetSeatCodes、areaInfoList

   [4] 锁座 → seatManage.lockseatByApp()
       └─ 凤凰锁座参数：cinemaLinkId、scheduleId、scheduleKey、seatCodes

   [5] 获取座位价格（seatPayTotalPrice）→ cardQuanManage.getSeatPrice()
       └─ 调接口获取座位支付总价（按 seats 数组），返回分单位，除以 100

   [6] 使用卡券 → cardQuanManage.useQuanOrCard()
       └─ 返回 canUseCardList、useQuan、profit、quanStock

   [7] 计算价格 → orderManage.priceCalculation()
       └─ 含 promotions 参数（券信息）

   [8] 🔑 创建订单（创建即支付）→ orderManage.createOrder()
       └─ 凤凰创建订单接口 = 已完成支付
       └─ 参数包含 payments（含 payToken）、promotions 等
       └─ 返回 orderId

   [9] 若 createOrder 无 orderId → 延迟 3 秒从 getOrderInfoByOrderList 获取

   [10] 获取取票码 → orderManage.getPayResult()
        └─ 含 getQrcodeUploadByPlat 上传

   [11] 异步取票码 → orderManage.asyncFetchQrcodeSubmit()
```

**凤凰关键特殊逻辑**：

- **创建订单即支付**：与辰星/金逸等"创建订单 → 再购买"两步不同，凤凰一步完成
- **payToken 机制**：需要 `member_pwd` → `window.getPayToken(member_pwd)` 生成支付令牌
- **测试模式**：不创建订单（因为创建 = 支付），只打印参数 + 释放座位
- **按票数获取座位价格**：更准确反映实际支付价格

### 4.7 金逸（jinyi_applet）

#### 基本信息

- **app_type_code**：`jinyi_applet`
- **涉及的具体影院（appFlag）**：`jinyiguangmei` 等

#### 报价流程

**入口**：`jinyi/offerManage.js` 的 `getJinyiOfferPrice.getEndOfferPrice()`

流程与辰星类似。注意：金逸报价时 `offerRule` 和 `currentParamsList` 为 `undefined`（同辰星的延迟初始化模式）。

**会员价获取**：

- 从座位数据获取区域价格
- 取不包含"默认区"（DEFAULT_AREA_NO=1）的座位区域最高价
- 最多取 10 个候选座位的价格作为参考

#### 出票流程

**入口**：`jinyi/buyTicket.js` 的 `JinyiBuyTicket.oneClickBuyTicket()`

```
⑤ oneClickBuyTicket(item) — 首次出票：

   [1] 延迟初始化 cardQuanManage、cinemaManage（同辰星）

   [2] 获取购票前影院信息 → cinemaManage.getBuyPrevCinemaInfo({cardQuanManage})
       └─ 同辰星模式：包含登录排序、可用卡列表

   [3] 获取目标座位 → seatManage.getTargetSeat(buyTicketInfo)
       └─ 失败 & 猎人平台 → applyChangeSeat

   [4] 锁座 → seatManage.lockseatByApp()
       └─ 返回 lockOrderId

   [5] 计算价格 → orderManage.priceCalculation()
       └─ 参数含 card_id、quan_code(voucher_code)、discount_type

   [6] 使用卡券 → cardQuanManage.useQuanOrCard()
       └─ 返回 canUseCardList、useQuan、profit

   [7] 🔑 金逸特殊：无可用卡券时，按报价类型处理
       ├─ offer_type="1" 且无券 → 转单/换号
       └─ offer_type ≠ "1" 且无卡 → 转单/换号

   [8] 创建订单 → orderManage.createOrder()
   [9] 购买 → orderManage.buyTicket()
   [10] 获取取票码 → getQrcodeUploadByPlat()
```

**金逸关键特殊逻辑**：

- **无释放座位/取消订单接口**：`releaseSeat()` 和 `cancelOrder()` 都返回 `{msg: "无释放座位接口"}` 或 `{msg: "无取消订单接口"}`，即金逸不支持主动释放
- **用券券单处理**：offerType="1" 时走券购买流程，用 voucher_code 参数
- **价格计算参数**：与辰星/凤凰不同，金逸的 `priceCalculation` 有 `discount_type: "MARKETING"`、`voucher_code`、`voucher_code_type: "VISTAX_VOUCHER"` 等参数
- 其他（延迟初始化、影院匹配、登录排序、锁座重试）同辰星模式

### 5.3 关键架构差异

| 维度                | SFC 模式（全初始化）                  | 辰星/凤凰/金逸 模式（延迟初始化）                                                                                                    |
| ------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 影院/卡券模块初始化 | 构造函数中 `initModules()` 一次性完成 | `initModules()` 只初始化 seatManage、orderManage、platManage；cinemaManage 和 cardQuanManage 在 `oneClickBuyTicket` 首次调用时才创建 |
| 原因                | 报价规则在构造函数调用时已可用        | 报价规则在 `getOrderOfferRule()` 之后才可用，cardQuanManage/cinemaManage 依赖 offerRule                                              |
| 影院+登录+卡券处理  | 分散在 buyTicket 各步骤               | 集中在 `cinemaManage.getBuyPrevCinemaInfo({cardQuanManage})`                                                                         |

| 维度           | SFC/UME/H5UME/LMA                  | 辰星/凤凰/金逸                                         |
| -------------- | ---------------------------------- | ------------------------------------------------------ |
| 子模块组织形式 | 每个模块独立，buyTicket 编排调用   | cinemaManage 聚合影院+影片+场次+登录排序，其他模块独立 |
| 代码复用风格   | 使用 `common/` 工具函数 + 手动编排 | 使用 `common/` 工具函数 + cinemaManage 内部聚合        |

### 6.3 关键决策点

在实现新系列时，需要回答以下问题来决定代码结构：

| #   | 决策问题                    | 影响范围                                                                       |
| --- | --------------------------- | ------------------------------------------------------------------------------ |
| 1   | API 是否有版本差异？        | 如辰星 3.0C/C，需在 offerManage/buyTicket 中处理版本分支                       |
| 2   | 订单创建机制                | 创建后购买 vs 创建即支付（凤凰） vs 锁座即创建（LMA）                          |

| 4   | 影院匹配方式                | 编码精确匹配 → getTargetCinemaCommon 降级                                      |
| 5   | 影片/场次匹配               | 可用 resolveMovieAndShow 公共工具（需在 SERIES_CONFIG 添加配置），也可手动实现 |
| 6   | 座位匹配方式                | 座位名解析方式（SFC 用 item[5]，其他用 seatName）                              |
| 7   | 座位价格获取方式            | 从座位布局区域价 vs 调接口获取                                                 |
| 8   | 是否使用延迟初始化          | 若 cardQuanManage/cinemaManage 依赖 offerRule，建议参考辰星/凤凰/金逸模式      |
| 9   | 是否有释放座位/取消订单接口 | 如金逸无接口                                                                   |
| 10  | 取票码获取方式              | 同步 vs 异步轮询                                                               |
